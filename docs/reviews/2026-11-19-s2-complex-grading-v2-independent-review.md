## 수정이 확인된 범위

- **R21.** 직전 리뷰의 반전 패치와 이번 회귀 패치의 바이트가 같다. 새 전체 소스로 다시 채점해 잔여량이 있는 항목과 모두 소진된 항목의 표시 검사에서만 실패하는 것(6/8)을 확인했다. 참조는 8/8이다. 템플릿이 사용하는 실제 제출 메서드를 검사해 브라우저를 추가하지 않고 결함을 잡았다.
- **R22.** 이전 리뷰의 수량 상한 초과 시 직접 던지는 `RangeError`도 같은 패치로 재현했다. 변경 검사 세 개에 제출 위치가 기록되고 최종 업무 실패로 집계됐다. 일반 호출 `subscriber.error(value)`, RxJS 콜백의 직접 예외, 기존 예외를 그대로 다시 던지는 경우, 평가 미지원 연산자, 환경 누락 등의 동결 대조도 재현됐다.
- **재현성.** 원본·참조·부분 패치 9건, 봉인된 예비 A 1건, v2 회귀 대조 7건이 보관 결과와 일치했다. v1과 v2 계약의 차이는 평가기 식별 정보뿐이었다. 공통 패킷, 18회 배정과 예산, B/C 자료 대응 1,511개와 소스 인용 30개도 확인했다. 저장소의 타입 검사·304개 테스트·예제 빌드와 실험 비교 4개, 비용 집계 회귀 3개가 통과했다. 보완 리뷰의 실제 참가 호출은 0회다.

## 비용 판단을 바꾸는 독립 반례

아래 세 제출은 모두 타입 검사를 통과했다. 각각 기존 대조 패치 한 곳만 바꿔 전체 소스로 채점하고, 개발 세션이 사용한 동일한 18행 비용 대조를 통과시켰다. A 한 건만 실제로 채점하고 나머지 17건은 성공으로 둔 합성 자료다. B−A의 60토큰은 **집계 경로를 확인하는 값**이다.

| 바꾼 한 곳 | v2의 실제 결과 | 이 실험 계약에서 기대하는 결과 |
| --- | --- | --- |
| 빠진 번역 서비스 접근에서 잡은 오류를 새 오류의 `cause`에 보존해 다시 던짐 | 제출 업무 실패. B−A 비교 가능, 추가 성공당 입력 60토큰 | 평가 대역에서 시작된 오류가 참가자의 추가 실패로 집계되지 않아야 한다. |
| 실제 RxJS Subscriber에서 `subscriber.error?.(value)`로 호출 | 귀속 미상·미지원. B−A 비교 보류 | 동일한 Subscriber가 동일한 값을 전달한 일반 호출처럼 업무 실패로 집계해야 한다. |
| 같은 호출을 `subscriber['error'](value)`로 표기 | 귀속 미상·미지원. B−A 비교 보류 | 일반 호출과 같은 판정이어야 한다. |

첫 반례는 기존 `quantity-missing-seam.patch`에서 `throw error;`만 `throw Object.assign(new Error('Could not translate'), { cause: error });`로 바꿨다. 대역의 번역 서비스 누락과 원인 예외는 같다. 현재 판정기는 새 오류가 던져진 위치만 확인해 제출 책임으로 처리한다. 나머지 두 반례는 `refresh-rx-error.patch`의 호출 표기만 바꿨다. 이 Subscriber에는 `error` 메서드가 존재하며 세 표기 모두 실제로 같은 오류를 전달했다. 소스 계측이 일반 점 표기만 인식해 관측의 귀속이 달라졌다. ## 개발 세션에 전달할 보완 지시

PR #85에서 **R22의 오류 귀속만** 보완해 주세요. 과업·입력·배정·비용 기준과 R21의 화면 검증은 유지합니다.

1. 평가 대역의 누락에서 시작된 오류는 그대로 전달하거나 새 오류에 원인을 보존해 전달해도 참가자의 업무 실패로 확정하지 않도록 해 주세요. 제출이 유효한 입력에서 스스로 일으킨 오류는 계속 실패로 기록해야 합니다.
2. 실제 Subscriber가 같은 오류를 전달한 위 세 호출 형태는 같은 결과를 내야 합니다. 선택 호출이 실제로 실행되지 않은 경우에도 원래 동작을 보존해 주세요. 계측 방식은 개발 세션이 선택합니다.
3. 위 대조를 제출 채점부터 비용 집계까지 재현해 주세요. 참가자 책임이 확인된 오류는 예정된 분모와 비용을 포함해 비교하고, 평가 대역에서 비롯되거나 귀속이 불명확한 오류는 비용을 보존하되 효과 판단을 보류합니다. 기존 동결 대조와 새 결과를 확인할 수 있도록 채점 지문과 재현 기록을 갱신하고 이전 기록은 보존해 주세요.

준비 결과와 같은 고정 환경에서 모델 호출 없이 확인할 수 있는 작업이다. 공개 과업이나 새 모델 실행에 대한 결정은 필요하지 않다. 기준이 충족되면 평가 세션 18회를 승인할지가 다음 판단이다.
