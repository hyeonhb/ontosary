**한 차례의 대리 인계는 합의한 조건을 충족했다.** 작성자의 주문 예가 후속 변경 제안에 재사용됐고 그 제안의 판단 기준은 변경 전 소스와 맞는다. Ontosary가 기여한 지점은 검색으로 찾은 메서드 위치의 재확인이었다. PR #120의 `5f7be80`에서 결과를 바꿀 결함을 발견하지 않아 병합했다. ## 인계가 일어났다는 근거

로컬에 남은 두 CLI 프로세스의 원시 이벤트에서 서로 다른 대화 ID와 작성 종료 이후의 후속 시작을 확인했다. 역할별 최초 안내와 프롬프트, 작성·후속 셸 작업 18·13건의 종료 이벤트, 두 원본 사본의 고정 Git 파일 각 4,735개를 대조했다. 최초 HANDOFF, 후속 세션이 받은 파일, 공개된 기록의 SHA-256이 같았다. 후속 최초 응답도 공개된 PROPOSAL과 바이트가 일치했다. 이 확인은 실제 전달물과 관측된 실행 경로에 관한 것이다. [공개 실행 기록](../../experiments/first-use/partial-fulfillment/results/2026-11-27/receipts.json)

후속 agent가 인계 파일을 읽은 순서에 더해 내용의 재사용도 확인했다. 작성자가 구성한 두 행의 주문 수량 5·3, 출고 상태별 수량, B의 재고 추적 전환이 후속 회귀 사례에 이어졌다. 후속 agent는 설정 수신 전의 빈 상태에서 안내를 숨기는 방법과, 운영자가 선택량만 0으로 바꾼 경우를 별도로 설명했다. 모든 판단을 작성자에게서 받았다고 볼 수 없고, 어떤 판단을 재사용했는지 특정할 수 있다. ## 동작과 비용 검산

고정 Vendure 소스에서 추출한 메서드로 작성자의 단언 9개가 통과했다. 두 행의 상한이 모두 0이면 상세 화면은 창을 열 수 있고 출고 제출은 비활성이다. B의 재고 추적만 끄면 상한은 0·2이고 제출할 수 있다. 그 상태에서 B의 선택량만 0으로 바꾸거나 양식만 무효화하면 상한은 그대로이고 제출만 비활성화된다. 따라서 후속 제안처럼 설정 수신 뒤 행별 상한을 보면 안내가 필요한 경우를 가려낼 수 있다. 안내 렌더링·실제 서버 출고는 이번 관측 범위 밖이다. [재현 예](../../experiments/first-use/partial-fulfillment/results/2026-11-27/author-example.cjs)

역할별 종료 기록과 원시 `turn.completed`를 대조했다. 두 세션 경과의 합은 206.214초(122.851 + 83.363), 합산 입력은 413,750토큰(캐시 입력 292,096 포함), 출력은 7,763토큰이다. 설치·역할 전환을 포함한 전체 경과나 청구액으로 환산하지 않는다. 요청 모델과 추론 설정은 두 세션 모두 동일하고 서버 측 모델 식별은 미확인이다. 독립 리뷰의 참가 모델 재호출은 0회다. 저장소 검사는 299개가 통과했고 과거 Vendure 임시 캐시가 필요한 5개가 생략됐다. 기존 예제 비교는 4/4가 통과했다.

## 제품 판단

작성자는 일반 검색과 TS·HTML 원문으로 핵심 파일을 먼저 찾았다. 이후 실행한 `scan`의 조회 명령에는 이미 알아낸 메서드 이름과 경로 필터가 들어 있다. `concepts`는 기본 상한에서 종료됐다. 이 사례가 보여 주는 가치는 근거를 담은 도메인 기록을 다른 agent가 읽고 새 과업에 재사용할 수 있다는 점이다. 무기록 대조가 없어 추가 성공·시간 절감은 미측정이고, FCA의 작성 기여와 사람의 첫 사용성도 열린 질문이다. 별도 보완이나 재실행 없이 이 관찰을 마감한다.
