# Vendure #4348 · 참가 패치 채점 준비 결과

**네 제출을 각각 새 변경 전 사본에 적용해 같은 여섯 업무 동작으로 채점했다.** 원본과 부분 수정은 각각 4/6이지만 실패한 가격 방식이 반대였다. 업스트림 제품 패치와 별도 파일의 헬퍼를 호출하는 정상 패치는 모두 6/6이었다. 헬퍼만 잘못된 계산으로 바꾼 대조에서는 같은 호출부가 4/6으로 돌아갔다. 참가 모델 호출은 예비 실행 포함 **0회**다. ## 어떤 제출을 실행했나

평가자용 준비기만 업스트림 해결 커밋에서 제품 파일을 꺼낸다. 제출 채점 명령은 부모 `8dbb6e4063248c3084e5768d613347a3453eda41`을 별도 디렉터리에 체크아웃하고, 받은 패치 바이트를 표준 `git apply --index`로 적용한다. 빈 바이트는 원본이다. 이름이나 정답 리비전을 채점 입력으로 받지 않는다. 재현 시 채점용 원격에는 부모 한 커밋만 넣었으며 해결 커밋 객체가 없음을 검사했다. [단일 제출 채점 명령](../../experiments/domain-model/s2/trial/angular-shipping/submission/grade.py) · [평가자 패치 생성·검증](../../experiments/domain-model/s2/trial/angular-shipping/submission/reproduce.py)

| 제출 | 패치 SHA-256 앞 12자리 | 적용 후 Git 트리 앞 12자리 | 실제 실행한 변경 |
| --- | --- | --- | --- |
| 원본 | `e3b0c44298fc` | `baef472d23e0` | 빈 패치, 부모의 차감식 |
| 부분 수정 | `300e93e99118` | `cc4586dfe316` | 세후 배송비를 항상 차감 |
| 업스트림 정상 | `2cdb4cbc1e3c` | `8efb318b3ea0` | PR #4370의 제품 변경만 적용 |
| 헬퍼 정상 | `579bc582b332` | `24c307787395` | 수정된 호출부에서 새 TS 파일의 `cancellationAmount`를 import해 실행 |

채점기는 실제 사본에서 읽은 제품 파일의 SHA-256을 기록한다. 네 대조의 모든 변경 파일에서 적용 후 해시와 로더가 읽은 해시가 일치했다. 헬퍼 사본의 전체 취소 네 사례에서는 호출부와 헬퍼가 각각 한 번 실행됐다. 배송을 유지한 두 사례에서는 서버 취소 메서드는 실행됐고 헬퍼 호출은 0회였다. 재현 명령으로 원본 패치 바이트, 적용된 독립 작업 사본, 사례별 호출 기록을 함께 확인할 수 있다.

## 실패와 판정 불가의 구분

- **패치 적용 거부.** 부모에 없는 이전 차감식을 문맥으로 적은 패치는 Git이 적용 단계에서 거부했다. 원래 진단과 패치 지문을 보존했으며 사례 실행은 0건이다.
- **관측한 업무 실패.** 원본과 부분 수정에서는 정상적으로 실행을 마친 사례의 금액을 기댓값과 비교해 각각 2건 실패로 판정했다. 헬퍼 본문만 바꾼 추가 대조도 원본과 같은 두 사례에서 200을 남겼다.
- **관측 경로 밖의 변경.** 정상 차감식에 관측기가 건너뛰는 상위 주문 서비스의 변경을 더하면 실행 전 6건 판정 불가다. 정상 차감식과 함께 같은 메서드의 ‘빈 상품 선택’ 분기를 바꾼 대조에서는 여섯 금액 모두 0 또는 보존 기댓값이었지만 그 변경문은 한 번도 실행되지 않았다. 금액은 기록하고 6건 모두 판정 불가로 남겼다.
- **대역에 없는 데이터.** 배송 차감이 채널 대역에 없는 `defaultTaxZone`을 읽게 한 대조는 전체 취소 4건에서 해당 필드와 함께 판정 불가다. 해당 필드를 읽을 필요가 없는 배송 유지 2건은 원래 금액으로 통과했다.

프로그램은 Angular 분기·대화상자가 만든 취소 입력 및 환불액, 서버의 상품별 취소·배송비 계산, 메모리 저장소에 건넨 주문의 금액을 관측한다. 취소 입력을 서버 메서드에 넘기는 구간은 관측기가 연결한다. 브라우저 클릭, 실제 GraphQL 전송, DB 재조회, 결제사 환불 완료와 Vendure 전체 타입 검사는 이번 관측 범위 밖이다. [공통 사례 관측](../../experiments/domain-model/s2/trial/angular-shipping/observe.mjs)

이번에 확인한 변경 범위는 상품별 취소 메서드와 여기서 호출하는 헬퍼다. 새 헬퍼 모듈은 제출 사본에서 해석한다. 계산 위치를 다른 서비스나 UI로 옮긴 제출, 관측하지 못한 의존성·삭제 위치·호출에 대해서는 성공 여부를 보류한다. 이러한 제출이 실제로 나오면 해당 경로를 관측할 수 있는지 먼저 검토한다. 호출·문장 기록은 선택한 여섯 사례의 근거이며, 모든 표현식의 분기 커버리지나 Vendure의 모든 행동을 보장하지 않는다. ## 독립 재현

macOS의 기존 `sandbox-exec`, Node 22.19.0, Python 3.12.10, Git 2.50.1, Ontosary의 잠금 의존성을 사용했다. 출력 디렉터리는 새 경로여야 한다. Vendure Git 사본이 이미 있다면 복제를 생략한다.

```sh
pnpm install --frozen-lockfile
scratch=work/shipping-grading-review
mkdir -p "$scratch"
git clone --bare --single-branch --no-tags https://github.com/vendurehq/vendure.git "$scratch/vendure.git"
grader=experiments/domain-model/s2/trial/angular-shipping/submission
python3 -B "$grader/reproduce.py" "$scratch/vendure.git" "$scratch/replay" --verify
```

원하는 패치 한 건은 같은 명령 진입점으로 다시 채점할 수 있다. 아래는 생성된 헬퍼 패치를 새 사본에 적용하고 첫 채점과 대조하는 예다.

```sh
python3 -B "$grader/grade.py" "$scratch/replay/parent.git" "$scratch/replay/helper.patch" "$scratch/one"
cmp "$scratch/replay/helper/grade.json" "$scratch/one/grade.json"
```

새 경로에서 보관한 전체 결과를 바이트 단위로 재현했다. 기존 선정 재생기도 당시의 원시 결과와 일치했다. `pnpm check`의 타입 검사·테스트 304개·예제 빌드와 `pnpm experiment`의 기존 비교 4/4가 통과했다. 참가 요청과 동결 B/C는 그대로다. 다음 A/B/C 독립 세 세션의 실행과 예산은 준비 결과 리뷰 뒤 결정한다.
