# 개발 지시문 — Ontosary에서 TypeScript 4.9.4 프로젝트 분석 검증

**Excalidraw를 업그레이드하지 않고, 그 프로젝트가 쓰던 TypeScript 4.9.4로 Ontosary의 코드 근거를 신뢰할 수 있게 추출할 수 있는지 검증해 주세요.** 현재 기준 버전은 5.9.3입니다. 같은 Excalidraw 사본이 자체 컴파일러에서는 진단 0개, Ontosary의 기준 컴파일러에서는 7개였습니다. 이번 결정 단위는 정확히 4.9.4 한 버전의 추가 지원 가능성입니다. [독립 검산과 원래 실행 조건](2026-11-27-excalidraw-eraser-independent-review.md)

## 개발 범위

개발 세션은 두 버전을 대조할 수 있는 최소 변경과 검증 방법을 정합니다. 기존 5.9.3 기본 경로와 공개 CLI·코어 호출자의 동작을 보존하면서, 실제 CLI 분석 경로에서 4.9.4를 사용할 수 있게 해 주세요. 임시 검증 옵션도 가능합니다. 사용자가 대상 프로젝트에서 확인한 버전과 **실제로 분석에 사용한 버전**을 구별할 수 있어야 합니다. 버전이 없거나 미검증이거나 선택에 실패한 경우에도 다른 버전의 결과를 요청한 버전의 성공으로 보고하지 마세요.

한 번의 분석에서는 설정 해석, 프로그램과 타입 검사기 생성, AST 판별, 심볼·조건 추출까지 일관된 컴파일러를 사용하세요. 현재 분석기와 조건 정규화 코드가 각각 TypeScript를 직접 가져오므로, 외부 `tsc`의 성공이나 진단 단계의 교체만으로는 판정할 수 없습니다. 기존 정적 분석 계약에 따라 대상 프로젝트의 코드를 실행하거나 수정하지 않는 방식으로 검증하세요. 패키지 배포 방식이나 버전 자동 탐색 전반을 이번에 확정할 필요는 없습니다.

## 검증할 사례

| 사례 | 확인할 결과 |
| --- | --- |
| **실제 Excalidraw 정상 입력** | 소스 `3bdaafe4b5ecde577fe9b5c69a5d1819e37c4ccb`, 당시 lockfile, `packages/excalidraw/tsconfig.json`을 고정합니다. 같은 사본의 4.9.4와 5.9.3 결과를 대조하고, 4.9.4 공개 CLI scan이 오류 없이 `eraserTest`와 `intersectElementWithLineSegment`의 실제 선언 위치를 찾는지 확인하세요. 선언 출력 전용 설정과 무출력 분석 옵션의 처리도 재현 명령에 남겨 주세요. |
| **실제 타입 오류가 있는 입력** | 작고 정상인 사본에 명백한 타입 오류 하나를 추가해 같은 경로로 분석하세요. 해당 위치의 컴파일 오류가 보고되고 기존 계약대로 concepts·compare가 중단되는지 확인하세요. 진단 누락이나 파일 제외로 정상 사본만 통과시키는 구현을 가려내기 위한 대조입니다. |
| **타입을 사용하는 분석** | 기존 별칭·동명 심볼 또는 유한 조건 회귀 사례를 재사용해 두 버전에서 올바른 선언과 근거를 참조하는지 검산하세요. 작은 정상 입력에서는 concepts가 후보 단계에 도달하고 compare가 기대한 판정을 내리는지도 확인하세요. 각 버전의 정당한 타입 표현 차이는 근거와 함께 설명할 수 있습니다. |
| **기존 사용자 경로** | 기본 5.9.3 사용 시 기존 명령·출력 소비자·종료 코드의 회귀를 확인하고, 미검증 버전 한 사례에서 사용자가 실제 분석 상태를 알 수 있는지 보여 주세요. |

## 완료와 인계

결과 PR에서 4.9.4 추가 지원을 권할 수 있는지, 그 근거와 남은 제약을 짧게 판정해 주세요. 고정 소스와 사용한 두 컴파일러, 실행 명령, 진단·심볼 근거·조건 비교 결과를 연결하고 `pnpm check`와 `pnpm experiment` 결과를 기록하세요. 공통 경로를 유지하기 어렵거나 기존 호출 계약을 바꿔야 한다면, 재현된 실패와 필요한 변경 범위를 제시한 뒤 설계 리뷰로 인계해도 됩니다. 다른 4.x·5.x 전체의 지원을 선언하는 결정은 이 검증 뒤에 합니다.

Excalidraw 패키지 전체의 FCA 후보 생성은 완료 조건에서 제외합니다. 진단이 사라진 뒤 기존 FCA 입력 상한에 도달하는 것은 서로 다른 단계의 결과입니다. 이번 회차는 컴파일러 호환성에서 마감하며, 동결 기록·화살표 참가 자료·FCA 범위와 상한은 별도 과업에서 다룹니다. A/B/C 참가 모델 호출은 선정 결과와 별도로 실행 조건을 합의한 뒤 진행합니다.
