## 판정과 인계

결과 PR에는 독립 리뷰어가 **어느 제출을 적용했고 어느 소스를 실행했는지** 확인할 근거, 네 제출의 사례별 기대값·실제값, 재현 명령을 남겨 주세요. 기존 역사적 결과는 보존하고 새 결과를 기록해 주세요.

판정은 관측한 단계에 맞춰 주세요. 패치 적용이 거부되면 그 단계와 이유를, 실행한 제출이 잘못된 값을 내면 해당 사례와 값을 기록합니다. 채점기가 제출의 변경 경로를 실행하지 못하거나 원인을 귀속할 수 없으면 해당 동작은 **판정 불가**로 남깁니다. 미실행 경로에 성공 점수를 주거나 채점기 오류를 업무 실패로 집계하면 안 됩니다. 런타임 수집·전송·영속성 중 실제 확인한 범위도 보고서에서 알 수 있게 해 주세요.

네 제출을 같은 경로에서 재현하고 위 판정을 설명할 수 있으면 이번 준비는 완료입니다. 기존 검증을 재사용하되, 새 DB·서버 환경이나 범용 평가기 구축이 필요해지면 확대 전에 막힌 제출과 동작, 가능한 대안과 예상 비용을 공유해 주세요. [참가자 요청](../../experiments/domain-model/s2/trial/angular-shipping/public/request.txt)과 동결 B/C는 그대로 사용하고, 해결 패치·헬퍼 대조·정답값은 평가자 자료로 둡니다.

후속 실행안은 같은 모델·추론 설정·시간 한도에서 A(공통 소스·문서), B(구조화 모델 추가), C(대응 서술 자료 추가)를 독립 세션으로 한 번씩 비교하는 것입니다. 수정 전에는 두 취소 경로의 공통 지점과 금액 결정 위치를 뒷받침하는 코드 근거를, 수정 후에는 여섯 동작의 성공·회귀, 첫 제출까지의 시간, 실패를 포함한 토큰 사용량을 비교할 예정입니다. 실제 세 세션의 실행과 예산은 이 준비 결과를 리뷰한 뒤 승인합니다.
