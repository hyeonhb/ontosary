# S2 smoke R20 진단 예산과 안전 정리 분리 지시

2026-11-18 후속: 이 문서는 이력으로 보존한다. 실제 보완에는 [목적·완료 기준 중심의 개정 지시](2026-11-18-s2-r20-outcome-instructions.md)를 적용한다.

[독립 리뷰](2026-11-18-s2-vm-cli-smoke-independent-review.md)의 R20을 기존 smoke 도구 안에서 보완한다. 이번 범위는 **로컬 코드·가짜 외부 명령 회귀·저장 증거 대조뿐**이다. 새 VM/실제 limactl 제어/CLI binary 실행/trace/정책 변경/인증/provider/model/본 비교는0회다. EROFS 원인을 해결하려고 guest 설정을 변경하지 않는다. 개발 세션의 작업 상한은 읽기·수정·검사·보고를 포함해45분이며 시간 부족 시 부분 결과를 남기고 runtime 시험으로 전환하지 않는다.

## 기준과 수정 범위

대상은 PR #70 head `2008351`의 `experiments/domain-model/s2/trial/vm-cli-smoke/run.py`, `bounded.py`와 관련 회귀다. 작업 전 AGENTS/PROGRESS/ARCHITECTURE/ROADMAP·Git 상태를 확인한다. PR #70 브랜치에서 보완하되 최신 main의 문서 변경을 통합하고 기준을 기록한다. 과거2026-11-17 증거·freeze·원문·code hash는 보존한다. 공유 runtime/제품/평가/준비물은 변경하지 않는다.

원인은 safety=True가 deadline만 분리하고 진단 cap에 따른 process kill은 그대로 적용하는 것이다. log4MiB−64KiB에서 cap=0, stop/delete가 진행 문구를 출력하면 완료 전에 SIGKILL된다. 이 구조를 그대로 둔 채 로그 상한만 늘리거나 재시도로 해결하지 않는다.

## 구현 순서

1. 실제 `Smoke.cleanup()`→`cmd()`→capture 경로를 사용하는 회귀를 먼저 추가해 현재 실패를 재현한다. 외부 실행 파일만 작은 가짜 limactl로 대체한다. 진행 문구→짧은 대기→상태 변경의 순서를 갖게 하고, list는 가짜 상태 파일을 조회한다. 각 파일1MiB 이하로 누적 진단 예산을 채우며 예산 여유 대조도 둔다.
2. **안전 동작의 실행/유한 종료와 진단 보존을 분리**한다. stop/delete는 저장 한도를 넘더라도 출력 때문에 죽이지 않고 남는 바이트를 bounded drain/discard하거나 명시적 폐기 sink로 보낸다. 시간 초과 때의 process-group 종료는 유지한다. 전체 출력을 메모리에 쌓거나 로그 예산을 늘리지 않는다. 일반 실험 명령의 출력 초과 시 중단 동작은 유지한다.
3. list/프로세스 조회는 absence 판단에 필요한 완전한 유한 응답을 받아야 한다. 고정된 작은 제어 응답 예산을 일반 로그와 분리하거나 사전 reserve로 확보하되 기존 회차 진단4MiB/스트림1MiB 저장 상한을 넘기지 않는다. 잘린 출력·timeout·파싱 오류·조회 실패를 빈 목록/부재로 해석하지 않는다. 관측할 수 없으면 unconfirmed로 남긴다.
4. 로그 용량 계산/stat·원문 파일/metadata 저장 오류가 stop/delete 호출을 막지 않게 한다. 유효한 소유권 확인은 그대로 필수다. 정리 동작 오류와 진단 기록 오류를 분리해 반환하고, 기록 실패가 확인된 경우 감사 완료라고 표현하지 않는다. 새 로그를 쓸 수 없어도 다음 안전 동작을 계속 시도한다.
5. 수정 뒤 새 오프라인 결과와 보고서를 추가한다. 기존 실제 EROFS 차단 결과를 성공으로 바꾸거나 frozen 코드를 현재 코드로 덮어쓰지 않는다.

새 범용 실행/봉인 프레임워크를 만들지 않는다. 기존 helper에 명시적인 안전 명령 출력 정책을 추가하는 등의 가장 작은 구조를 선택한다. 정리시간은 유한하게 유지하고 expired experiment가 안전 정리 호출을 취소하지 않게 한다.

## 검증

- 예산 여유와 예산 소진 모두에서 가짜 stop/delete의 완료 상태 변경이 실제로 발생한다. 단순히 호출 목록에 추가됐다는 확인으로 대신하지 않는다.
- stop/delete가 자체 capture cap보다 많은 출력을 생성해도 저장/메모리 상한을 지키면서 완료한다. 일반 실험 명령의 출력 초과는 여전히 중단된다.
- 이미 만료된 experiment 마감, 로그 용량 조회 실패, stdout/stderr/command metadata 저장 실패에서도 소유 stop/delete를 시도한다. 진단 실패가 있었다는 정보는 보존한다.
- stop timeout/실패 후에도 delete/absence 확인을 시도한다. delete 실패로 부재 미확인·VM 잔존·list 출력 절단/오류·프로세스 조회 불명에서는 정리 완료나 disposed marker를 만들지 않는다. 실제 부재가 확인되면 앞선 오류와 최종 정리 상태를 함께 기록한다.
- 무한 출력/응답 정지가 timeout 안에서 종료되고, 시간 제한·소유권 거부·진단 총량 계약은 유지된다.
- `pnpm check`와 관련 Python 회귀를 실행한다. 제품/평가 의미가 불변이므로 `pnpm experiment`·Linux 전체 평가·새 runtime 반복은 하지 않는다.

과거 verifier는 freeze hash를 현재 파일과 대조하므로 run.py 변경 뒤 그대로 실행하면 실패할 수 있다. **고정된2008351 코드/검증기를 분리한 임시 소스 트리에서 과거 증거를 읽기 전용으로 대조**하는 등 원래 코드 identity를 유지한다. 필요하면 명시적인 frozen-source 입력을 지원하는 작은 오프라인 검증 연결을 사용하되 현재 코드로 대체하거나 mismatch를 무시하지 않는다. 과거98파일·121,674 bytes·argv/차단/폐기 관측이 불변임을 확인한다. 임시 트리에서 runtime 진입점을 실행하지 않는다.

## 완료와 인계

원래 반례의 실패→통과, 위 실패 경로의 실제 명령 완료/상태 판정, 출력/시간 상한, 기존 검사와 과거 관측 보존이 확인되면 R20 보완으로 인계한다. 보고서는 실제 날짜의 `docs/reviews/YYYY-MM-DD-s2-smoke-cleanup-budget-fix.md`와 새 작은 증거 디렉터리에 둔다. 실행한 회귀 수·명령·코드 hash·오류와 한계를 기록하고 PROGRESS/README를 실제 결과로 갱신한다.

PR #70에 커밋·push하고 **독립 보완 리뷰 전 병합하지 않는다.** PR #67은 별도로 유지한다. R20 해결과 EROFS 해결·C안 채택·R11 완료를 구분한다. 실제 EROFS 경로 진단을 위한 새 실행/trace와 추가 권한·모델 호출·본 비교는 이후 별도 결정이다.
