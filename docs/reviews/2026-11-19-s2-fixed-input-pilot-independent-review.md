# Vendure 주문 취소 고정 입력 파일럿 독립 리뷰

2026-11-19. 세 조건의 첫 패치를 독립 재채점해 보고된 만점을 확인했다. 이번 Vendure 과업에서는 소스와 업무 요구를 받은 A가 이미 모든 검사를 통과했다. 이 한 과업에서 B/C에 자료를 더 넣어 확보한 추가 통과는 0건이다. 더 어려운 과업에서 도메인 모델이 수정 성공률을 높이는지, 그때 비용이 얼마나 드는지는 열려 있다. [개발 보고서](2026-11-18-s2-fixed-input-pilot.md)

## 무엇을 확인했나

고정 Vendure 원문으로 참가 입력을 다시 만들고 봉인 기록과 대조했다. 세 세션은 서로 다른 스레드에서 각각 한 턴을 사용했고 도구 이벤트는 없었다. 원본의 기존 동작 16/16·변경 요구 6/36과 참조 패치의 16/16·36/36은 보존된 교정 기록에서 확인했다. 참가자 원응답 세 개는 각각 새 전체 소스에 적용해 기존 평가기로 다시 실행했다. 세 제출의 지문과 52개 사례별 관측이 당시 결과와 일치했다. 로컬 임시 Vendure 캐시의 누락 파일을 보존된 준비 환경에서 복구한 뒤 타입 검사·304개 테스트·예제 빌드가 통과했다. 파일럿 PR #82를 병합했다. 52개는 패치 한 개를 관찰하는 검사 수다. 조건별 독립 제출은 한 개다. C의 실행 시간이 가장 짧았지만 단발 지연 시간으로 운영 비용을 추정하기는 어렵다. 입력·출력 토큰은 관측된 추론 비용 지표이고, 도메인 모델 작성·승인·갱신에 든 비용은 별도로 측정해야 한다. B/C의 구조적 대응은 기록돼 있으나 두 자료가 업무상 같은 의미를 전달하는지에 대한 사람의 검토는 남아 있다. [실행별 점수와 사용량](../../experiments/domain-model/s2/results/2026-11-18-fixed-input-pilot/results.json)

## 변별력이 제한된 두 지점

공통 입력은 파일명 규칙으로 선별한 생산 TypeScript 파일 42개였고 세 제출이 고친 파일을 모두 포함했다. 공개 과업은 공백뿐인 사유의 처리, 혼합 취소·환불에서 보존할 값, 서비스가 값을 방출하지 않고 완료해야 하는 경우까지 설명했다. 원본 점수와 참조 점수에는 차이가 있어 평가기가 요청된 변경을 감지한다는 근거는 있다. 다만 참가자가 스스로 코드 간의 관계를 복원하거나 보존 조건을 찾아야 하는 부담은 작았다. 과업, 공통 입력, 모델 성능 각각의 기여는 이번 실행만으로 분리할 수 없다. [공개 과업](../../experiments/domain-model/s2/trial/task.ts) · [입력 선정기](../../experiments/domain-model/s2/trial/fixed-input/packets.py)

A와 B는 적용 후 소스가 같았다. C도 서비스와 두 대화상자에는 같은 코드를 냈다. 차이는 A/B만 주문 상세 화면의 두 분기를 `of(undefined)`에서 `EMPTY`로 바꿨다는 점이다. 값 방출 여부는 뒤쪽 구독 경로가 이력 갱신 신호를 보내는지에 영향을 줄 수 있다. 세 제출의 상세 관측은 모두 같아 실제 화면에서 그 차이가 발생하는지는 확정할 수 없다. C가 기존 동작을 더 잘 보존했다고 판정하거나 과거 점수를 소급해 바꿀 근거도 없다. 다음 과업에서 이 동작이 중요하다면 업무상 기대를 먼저 정하고, 두 구현을 구분하는 검사로 확인할 수 있다. ## 다음 비교 제안

같은 모델에 동일한 업무 요구와 충분한 소스를 주고, 변경 전 도메인 지식이 여러 경로에 걸친 보존 조건을 적용하는 데 도움이 되는지 먼저 본다. 기존 고정 입력·첫 패치·외부 채점 경로를 재사용하면 실행 환경을 더 구축하기 전에 이 질문을 다룰 수 있다. 실제 저장소에서 관련 코드를 찾는 비용과 FCA가 모델 구축을 돕는 정도는 독립된 후속 질문이다.

- **과업 선정.** 예를 들어 일부 라인만 취소할 때 이미 환불된 금액과 다른 결제의 환불 가능액을 보존하는 변경을 후보로 검토한다. 해당 정책이 실제 Vendure에 맞는지, A의 소스에 판단 근거가 있는지, 변경 전 B/C가 관련 관계를 같은 의미로 담는지를 먼저 확인한다. 참가자에게 새 정책과 성공 기준을 전달하되 구현 위치와 분기별 풀이까지 주는 방식은 피한다.
- **난이도와 채점 교정.** 별도 예비 과업으로 난이도를 가늠한 뒤 평가 과업과 예산을 고정한다. A가 실패한 사례만 골라 같은 사례의 B/C 결과를 전체 성과로 발표하면 효과가 부풀 수 있다. 평가에는 사전 선정한 과업과 A의 성공을 모두 포함한다. 국소 수정만 한 패치가 인접 업무 흐름을 깨뜨리는 사례와 올바른 참조 패치로 채점 범위를 확인한다.
- **추가비용.** 같은 과업별 예산에서 첫 패치가 변경과 보존 요건을 모두 만족한 건수를 우선 비교한다. 보조 자료를 포함한 실제 입력·출력 토큰을 기록하고, 추가 성공이 생기면 전체 실패 시도를 포함한 비용 차이를 추가 성공 건수로 나눈다. 사람이 지식을 만들고 유지하는 시간은 질의당 사용량과 따로 기록해 재사용 횟수에 따라 해석한다. 예산을 아끼려고 B/C 자료를 줄이면 대응하는 지식 단위를 같이 줄이고 의미 동등성을 확인한다.

이 설계는 후속 제안이다. 이번 독립 리뷰에서는 추가 참가 모델 호출을 수행하지 않았다.
