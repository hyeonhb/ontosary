## 편집기 최종 장면

upstream 아카이브 `e32836f799b65f978cbf4877eab7ffc42c6e6494`와 `a89a03c66ccbd3d44078be78a82d7adfb8f05953`를 새로 받아 각 사본에 의존성을 설치했다. 같은 Vitest에서 줌 1의 편집기를 마운트하고 (160, 70)에서 누른 뒤 (160, 140)으로 한 번 이동해서 뗐다. 원래 두 요소 장면을 먼저 검산하고, 같은 입력에 경로 밖 일반 화살표를 더한 대조도 실행했다. 두 사본에서 원래 ID별 삭제 플래그와 비삭제 장면 포함 여부가 일치했다.

| 원래 장면의 요소 | 변경 직전 | 변경 직후 |
| --- | --- | --- |
| 경로가 가로지른 일반 화살표 | 남음 | 삭제 |
| 경로가 가로지른 잠긴 화살표 | 남음 | 남음 |
| 추가 대조 장면의 경로 밖 일반 화살표 | 남음 | 남음 |

세 번째 요소는 보이는 잠금 해제 화살표를 일괄 삭제하는 수정까지 구별한다. 기존 올가미 테스트도 양쪽에서 각각 6/6 통과했다. 재현하려면 [선정 보고서](2026-11-27-excalidraw-followup-selection.md)의 설치 절차 뒤 [검토자용 관측 코드](../../experiments/first-use/excalidraw-followup/reviewer/arrow-probe.tsx)를 각 사본의 `packages/excalidraw/tests/fast-arrow.test.tsx`에 복사하고 아래 명령을 실행한다. 관측 코드는 대상 일반 화살표의 결과를 `ARROW_SCENE`으로 출력한다. 테스트 통과 수만으로 전후 차이를 판정할 수 없으므로 출력도 표와 대조한다.

```sh
./node_modules/.bin/vitest run packages/excalidraw/tests/fast-arrow.test.tsx packages/excalidraw/tests/lasso.test.tsx
```

## 향후 비교에서의 해석

참가자 요청은 upstream 화살표 정밀도 변경에서 재구성한 증상과 보존 요구다. 정답 파일·함수·좌표는 공개하지 않지만 잠긴 화살표가 남아야 한다고 명시한다. 이 문구를 모든 조건에 그대로 사용하면 잠금 보존은 **명시 요구 이행**으로 채점할 수 있다. 기록 덕분에 잠금 규칙을 스스로 발견했다는 근거로 점수를 부여할 수는 없다. 실제로 관찰할 만한 차이는 작업자가 서로 떨어진 두 포인터 표본으로 결함을 재현하는지, 경로 밖 요소를 보존하는 패치를 만드는지, 같은 품질까지 비용이 얼마나 드는지다. 후속 비교를 준비할 때 검토자 자료는 참가 입력 밖에 두고, 추적 가능한 판단과 비용을 사전에 정한다.

이 리뷰는 후속 과업과 관측의 타당성까지 확인했다. 기록을 받으면 작업이 개선되는지, FCA가 기록 작성에 얼마나 기여하는지, TypeScript 4.9.4를 Ontosary가 지원할 수 있는지는 별도 검증 대상이다.
