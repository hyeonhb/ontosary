## 업무 동작과 실패 단계

- **잔여 수량.** 환불 가능 여부를 판단하는 기존 메서드에 이미 여러 결제의 이력을 합산하고 실패한 환불을 제외하는 로직이 있었다. A도 이 근거를 수량 편집 상한에 재사용해 환불·동반 취소에 같은 수량을 보내고, 사용자가 해제한 취소 선택을 보존했다. 9개 제출 모두 8개 사례를 통과했다. [A의 첫 패치](../../experiments/domain-model/s2/results/2026-11-20-complex-comparison/attempts/7191b15de681/7191b15de681/answer.txt)
- **화면 동기화.** A의 독립 반복 세 번은 적용 후 전체 소스 지문이 같았다. 선행 취소 거절 뒤의 환불 중단, 여러 결제의 결과가 결정된 뒤 한 번 갱신하는 동작 등을 포함해 적용 가능한 7개 제출이 모두 24개 사례를 통과했다. [사례별 결과와 제출 지문](../../experiments/domain-model/s2/results/2026-11-20-complex-comparison/score/)
- **B의 두 실패.** 원응답을 고정 실행기의 줄바꿈 규칙대로 읽고 별도 Vendure 복사본에서 검사했다. 동결 규칙인 `git apply --check --recount`는 두 패치를 거부했다. 진단용으로 문맥 요구를 완화한 `--unidiff-zero`를 더하자 둘 다 적용 검사를 통과했다. 이 추가 진단은 타입이나 업무 정확성을 판정하지 않는다. 공식 분모는 각 조건 6건이며, 두 제출은 그대로 실패다. 두 차례의 거부를 구조화 뷰의 인과적 효과로 해석할 근거는 부족하다.

## 검증과 판단

동결된 순서와 18개 서로 다른 세션의 첫 제출·봉인·사용량을 대조했다. 새로 조립한 패킷과 고정 원본 전체 소스로 모델 호출 없이 재채점해 18개 등급, 사례별 관측, 비용표를 재현했다. 실패 시도를 포함한 전체 사용량은 입력 1,030,206·출력 11,639토큰이다. B−A의 추가 성공은 −2건, C−A는 0건이므로 추가 성공당 비용은 두 경우 모두 산출할 수 없다. 저장소 타입 검사·테스트 304개·예제 빌드, 비용 집계 회귀 3개, 기존 비교 실험 4개가 통과했다. [원응답과 봉인](../../experiments/domain-model/s2/results/2026-11-20-complex-comparison/attempts/) · [재현 검증기](../../experiments/domain-model/s2/verification/2026-11-20-complex-comparison/verify.py)

**재현 시 Python 버전에 유의한다.** macOS 기본 Python 3.9.6에서는 C의 누적 시간을 `112.96000000000001`초로 더해 기록값 `112.96`초와의 정확 일치 검사에서 멈췄다. 차이는 C의 시간 합계·관측 소계와 그로부터 계산한 C−A 시간 차이 세 필드에 한정된다. 봉인된 시도별 시간은 밀리초 단위로 합산하면 112,960ms다. 보고서의 재현 명령에는 Python 3.12.10을 사용하면 된다. 후속 실험에서 여러 Python 버전을 지원한다면 시도별 밀리초 정수로 시간을 합산하는 국소 개선이면 충분하다.

**현재 형태의 전체 B/C 자료를 두 과업의 Astra 기본 입력으로 채택할 근거는 얻지 못했다.** 두 과업의 모든 수정 대상이 공통 입력에 있었고 업무 요구도 명시돼 있었다. 이번 측정으로 알 수 있는 것은 이 조건에서 제출한 첫 패치의 성과다. 실제 저장소 탐색에서 지식이 관련 파일을 찾는 데 주는 도움, 유지관리 비용, FCA가 지식 구축에 기여하는 정도는 별도로 관측해야 한다. B/C의 업무 의미 동등성에 대한 사람의 최종 검토도 남아 있다.

다음 실험 후보로는 같은 두 과업과 자료로 Sol의 A/B/C를 비교하는 방안을 권한다. Sol 내부의 자료 제공 효과를 먼저 보고, 그다음 Sol+B/C가 Astra+A의 관측 품질에 어느 비용으로 도달하는지 판단할 수 있다. 모델을 바꾼 새 실험이므로 실행 횟수와 예산은 별도 합의 대상이다.
