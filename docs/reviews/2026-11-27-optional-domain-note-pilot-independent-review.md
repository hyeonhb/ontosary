# 선택형 도메인 기록 · 두 과업 독립 리뷰

**이 회차에서 기록 요청은 0/2였다.** 같은 변경 전 소스를 조사해 별도 agent에게 기록을 주문하는 기능을 첫 공개의 핵심으로 앞세울 근거를 얻지 못했다. 사전 계획과 첫 제출을 대조해 결과를 바꿀 결함을 발견하지 않아 [PR #126](https://github.com/hyeonhb/ontosary/pull/126)을 병합했다. [실행 결과](2026-11-27-optional-domain-note-pilot.md)

## 선택과 품질을 다시 확인한 결과

Vendure 첫 부모 이력에서 선정표의 11개 후보 순서를 재현했다. 진행자의 실행 기록에는 참가 시작 전 계획 커밋 `3827577`이 남아 있었다. 네 작업 사본은 과업별 변경 전 트리와 각각 일치했다. 실제 전달한 문구·두 턴의 응답과 공개 제출물을 대조했다. B는 두 건 모두 중간 조사 후 요청 선택지를 받았고 최종 계획을 제출했다. 진행자가 요청을 폐기한 흔적은 없었다.

- 결제·배송 B는 첫 조사에서 이미 활성 목록과 주문별 견적을 나눴다. A는 견적을 조사하다가 두 번째 턴에 활성 목록을 찾았다. 선택권을 알리기 전부터 탐색 경로가 달랐다.
- 상품 주소는 두 조건 모두 첫 조사에서 채널을 제한하기 전에 ID를 하나 고르는 문제를 짚었다. B가 남긴 의문은 두 채널에서 같은 주소를 만드는 테스트 자료에 관한 것이었다. 미요청 이유 자체는 두 B 모두 진술하지 않았다.

네 계획은 각 과업에 사전 지정한 다섯 항목을 다뤘다. 가림 평가는 같은 진행자가 수행했고 평가 단위는 제안서였다. 예를 들어 공개 필드가 없을 때 두 계획은 필드 생략과 null 반환을 각각 제안했다. 사전 항목의 5/5를 실제 구현의 동등성으로 읽으면 이 차이가 사라진다. ## 무엇을 마감할 수 있는가

공개 검증기와 로컬 원시 CLI 이벤트에서 네 대화와 최초 제출, 중복 없는 계측 응답 35개, 입력 661,252·출력 9,595토큰을 대조했다. B 두 건 모두 작성자 호출과 기록 전달이 없었다. B의 입력이 두 건 모두 적었다는 관찰은 성립하지만 기록으로 절약한 토큰은 추정할 수 없다. 리뷰 참가 모델 호출 0회, 저장소 검사 299개 통과·과거 임시 캐시 조건부 검사 5개 생략, 기존 예제 비교 4/4였다.

이번 선택지는 초기 조사 후 비용이 드는 추가 조사를 주문하는 것이었다. 두 과업 모두 Vendure 서버 코어의 변경 계획이었고, 작성자에게도 같은 변경 전 코드와 당시 공개 문서만 주도록 설계했다. 이미 검토해 둔 정책·예외를 다음 변경에서 조회하는 방식이나, 코드에서 드러나지 않는 업무 의도를 전달하는 방식의 효과는 여전히 미측정이다. 같은 질문으로 과업을 추가하지 않고 이 회차를 마감한다. 후속 투자 전에는 유지보수자가 남긴 이유나 예외가 실제 변경 판단을 바꾼 사례를 먼저 확인할 것을 권한다.
