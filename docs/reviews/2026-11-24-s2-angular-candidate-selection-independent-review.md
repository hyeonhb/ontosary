## 변경 전 자료가 실제 주문에 연결되는가

업스트림 신고는 세금 포함 채널에서 배송까지 취소한 뒤 배송 세액이 남는 현상이다. 해결 직전 소스에서 승인 결제의 직접 취소와 정산 결제의 환불 동반 취소가 같은 주문 취소 서비스를 호출하는 것을 확인했다. 두 화면은 취소할 상품 행을 제출하고, 서버는 이를 상품 행별 취소 메서드로 보낸다. 업스트림의 제품 코드 변경은 이 메서드에서 배송 행의 저장 가격에 세금이 포함됐는지에 따라 조정액을 고르는 한 곳이다. 환불 동반 취소와 배송을 유지한 일부 취소는 이번 비교에서 보존할 동작으로 추가한 사례다. [원 신고](https://github.com/vendurehq/vendure/issues/4348) · [변경 전 서버 분기](https://github.com/vendurehq/vendure/blob/8dbb6e4063248c3084e5768d613347a3453eda41/packages/core/src/service/services/order.service.ts#L1886-L1923) · [업스트림 변경](https://github.com/vendurehq/vendure/pull/4370/files)

감사기를 다시 실행해 동결 B 68개와 C 4개의 바이트, 대응 단위 1,511개, 부모의 파일 8개와 인용 위치 30개를 확인했다. 자료 기준 리비전은 해결 직전 부모의 조상이고, 두 가격 방식에 따른 차감식과 업스트림의 회귀 테스트는 참가자 자료에 들어 있지 않았다. 요청 초안은 두 화면에서 보존할 동작을 알려 준다. 따라서 수정 전 탐색의 성과는 요청에 쓰인 경로 이름을 반복했는지가 아니라, 각 경로가 어디에서 만나고 금액을 결정하는지를 해당 소스로 설명했는지로 판단할 수 있다. [자료 감사](../../experiments/domain-model/s2/results/2026-11-24-angular-selection/audit.json) · [참가자용 요청 초안](../../experiments/domain-model/s2/trial/angular-shipping/public/request.txt)

## 같은 입력에서 드러난 차이

감사와 동작 재생의 출력 모두 보관된 JSON과 바이트 단위로 일치했다. 아래 금액은 취소 후 세후 배송비다. 전체 취소는 두 화면에서 각각 관측했고, 일부 취소는 각 화면에서 한 사례씩 관측했다. 두 일부 취소 사례 모두 남은 상품을 포함한 세후 주문 합계가 1,300이었다. [사례별 세전·세후 배송비와 주문 합계](../../experiments/domain-model/s2/results/2026-11-24-angular-selection/behavior.json)

| 실행한 제품 코드 | 전체 취소 · 세금 포함 | 전체 취소 · 세금 별도 | 상품 1개만 취소 · 배송 유지 | 통과 |
| --- | ---: | ---: | ---: | ---: |
| 변경 전 | 200 | 0 | 1,200 | 4/6 |
| 세후 배송비를 항상 차감 | 0 | −240 | 1,200 | 4/6 |
| 업스트림 수정 | 0 | 0 | 1,200 | 6/6 |

원본과 부분 수정은 총점이 같아도 실패한 가격 방식이 반대다. 신고된 잔액을 없애면서 기존 정상 주문에 음수를 만드는 수정을 구별할 수 있다. PR head에서 `pnpm check`의 테스트 304개와 빌드, `pnpm experiment`의 비교 4개가 통과했다. 참가 모델 호출은 0회다.

## 실제 비교로 넘어갈 때의 판단

현재 재생기는 세 변형의 고정 소스에서 지정한 메서드를 꺼내 실행한다. 대화상자가 만든 취소 입력을 관측기가 서버 메서드에 넘기고, 저장소 대역이 기록한 객체에서 금액을 읽는다. API 전송, DB 재조회, 결제 환불 성공은 이 관측에 포함되지 않는다. 가령 참가자가 차감식을 새 헬퍼로 옮기면 정상 코드여도 발췌한 메서드만으로 실행할 수 없다. 선정 결과는 유효하며 이 재생기의 예외만으로 참가 패치를 오답 처리할 근거는 없다. [소스 로더](../../experiments/domain-model/s2/trial/angular-shipping/load-controls.mjs) · [동작 재생기](../../experiments/domain-model/s2/trial/angular-shipping/replay.mjs)

다음 결정은 이 과업의 채택과 A/B/C 실행 예산이다. 진행한다면 첫 호출 전 각 제출의 실제 변경 사본을 같은 여섯 동작으로 판정하는 방법과, 관측할 수 없는 패치를 처리하는 기준을 정한다. 수정 전에는 코드 근거를 갖춘 경로 발견을, 수정 후에는 가격 방식별 성공·회귀와 실패를 포함한 비용을 비교한다. A가 서버 코드만 찾아 전부 고쳐도 수정 성공으로 인정한다. 세 조건이 같은 결과를 내면 탐색·비용 차이를 보고하고, 한 과업의 관측을 FCA의 모델 구축 기여로 확대하지 않는다.
