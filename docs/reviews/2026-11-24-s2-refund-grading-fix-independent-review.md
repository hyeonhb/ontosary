## R23에 남은 범위

정상 A 사본의 **바깥 버튼**에 있는 노출 조건 끝에 `; then null`을 추가하고 같은 전체 소스 채점 경로로 검사했다. 고정된 Angular compiler 19.2.15는 유효한 문법으로 읽고 `ngIf`와 `ngIfThen` 두 입력을 생성했다. 같은 버전의 실제 `NgIf` 지시자를 뷰 생성·제거를 기록하는 컨테이너에 연결해 확인했다. 참인 조건에서 기본 템플릿은 뷰 한 개를 만들었고, `ngIfThen = null`을 적용한 뒤 남은 뷰는 0개였다. 전체 브라우저를 기동하지 않고 지시자의 렌더링 결정을 대조한 결과다.

PR 채점기는 이 사본에 **11/11과 최종 성공**을 부여했다. 버튼 구조 검사는 노출 조건의 추가 입력을 허용하고, 실행 경로는 `templateAttrs`에서 `ngIf` 하나만 골라 계산한다. 그 결과 실제 버튼이 없는 사례에서도 문구와 클릭을 관측한 것으로 기록한다. ## 개발 세션에 전달할 종료 조건

PR #96에서 바깥 버튼의 Angular 바인딩 입력 중 관측기가 해석하지 않는 입력을 조용히 생략해 성공으로 처리하는 경로를 닫아 주세요. 위 `then null` 제출은 미지원으로 판정을 보류해도 충분합니다. 이미 지원하는 안쪽 문구의 `else cancelOnly`는 정상 동작해야 합니다. 같은 채점 경로에서 새 대조가 성공하지 않고, 기존 12개 대조와 로컬 요청의 결과가 유지됨을 보여 주면 이 보완을 마감합니다. 참가 모델 호출·추가 렌더러·새 VM·실행 예산 확대는 필요하지 않습니다.

평가 자료와 코드 근거를 사전 제공하지 않는 탐색 경로, 첫 수정 전 발견 기록, 독립 작업 사본 회수는 준비 종료 기준을 충족했다. 다음 실험의 우선순위는 한 곳의 수정만으로는 보존 요구를 충족하기 어려운 실제 Vendure 변경 하나를 고르는 일이다. 과업과 판정 범위를 보고 실제 참가 예산을 결정한다.
