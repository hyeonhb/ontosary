# S2 직접 VM CLI 타당성 중단 결과 독립 리뷰

2026-11-17. 검토 대상은 [PR #67](https://github.com/hyeonhb/ontosary/pull/67)의 `ed0250bd534bedfe994814bdf0a6920cb5eb727f`와 [개발 보고서](https://github.com/hyeonhb/ontosary/blob/ed0250bd534bedfe994814bdf0a6920cb5eb727f/docs/reviews/2026-11-17-s2-vm-cli-feasibility.md)다. **중단 기록의 inconclusive 판정은 타당하다. C안의 기술적 성립 여부는 미관측이며, 단순 예산 연장보다 검증 순서와 구현 범위를 먼저 줄여야 한다.** 비활성 초안의 새 기동 결함도 확인했다. PR #67은 미병합으로 두고 다음 범위를 사용자와 합의한다.

## 시간 부족의 의미와 지시의 문제

총90분을 소진한 것이 아니다. first-command/stop/round의 시각을 대조하면 시작은12:52:33.929495 UTC, 15분 gate는13:07:33.929495, 중단 감지는13:10:20이다. 감지 당시17분46.071초, 회차 종료까지30분31.075초였다. VM0·실제 sandbox0·필수 단위0/4로, 준비 단계에서 중단한 뒤 검사·기록을 마쳤다.

[지시문](2026-11-17-s2-vm-cli-feasibility-instructions.md)이 15분 내 최소 구현/실패 정리를 요구하면서 단계 마감 초과를 전체 실험 중단 조건으로 정했기 때문에 개발 세션의 중단은 계약에 부합한다. 2분46초 늦게 마감을 감지한 운영상 누락은 별도 남는다. 총상한만 늘리고 이 gate를 유지하면 같은 중단이 반복될 수 있다.

리뷰 세션이 작성한 지시의 범위 산정에도 문제가 있었다. C안의 첫 불확실성은 고정 CLI가 해당 VM의 비특권 사용자 문맥에서 내부 sandbox payload를 실행할 수 있는가였다. 그런데 이를 보기 전에 공개 바이너리 선택 추출, 새로운 host/guest/worker 감독 연결, 인증/네트워크 대조, 실패 수집, 증거 검증과 새 VM 반복까지 한 번에 준비하게 했다. 실제 기동 전 약549줄의 실행/추출/판정 초안과 추가 검증기가 생겼다. 검증된 컨테이너 기반 기능을 직접 VM에 연결하는 비용을 과소평가했고, 15분 완성을 강한 전제에 둔 것은 부적절했다.

## 독립 검증

원래 개발 checkout은 브랜치/내용을 변경하지 않고 읽기와 로컬 검증에만 사용했다. 새 VM·CLI binary 실행·정책 변경·실제 인증/provider/model 호출은0회다.

- `pnpm check`:304테스트·타입 검사·예제 build 통과.
- 새 Python25개, 기존 lifecycle16개, single-policy-test 디렉터리57개 통과. 이번 독립 실행은 Python98개다. 개발 보고서의 선택된 기존60개와 동일 분모라고 표현하지 않는다.
- 저장 verifier:18개 indexed 파일·과거3474파일을 대조하고 `consistent-inconclusive-record`, runtimeVerified=false, observedUnits=0/requiredUnits=4를 재현했다.
- 기존 공개 cache4개를 실제로 다시 읽어 SHA-256을 대조했다. body 합계1,706,231,724 bytes가 일치했다. guest 설치/호환성은 확인하지 않았다.
- 원래 제품·테스트·공유 container 구현의 diff는 없다. CLI entrypoint/host.execute는 비활성 상태이며 현재 production/live 경로에 연결되지 않았다.

hash와 중단 기록의 내부 정합성은 실제 격리·성능·실행 성공을 증명하지 않는다. cache 재사용 준비와 솔직한 미실행 판정은 인정하되 C안 채택이나 R11 해결로 승격하지 않는다.

## 새로 확인한 초안 기동 결함

두 항목을 **R19: 비활성 VM 초안의 기동 전제 불일치**로 기록한다. 현재 runtime 진입점이 거부하므로 제품 회귀나 실행된 격리 실패는 아니다. 이 초안을 재사용하는 경우 실행 전에 보완해야 하며, 거부문만 지워서는 안 된다.

1. **호스트 Python 계약 불일치.** `host.py:16`은 `hashlib.file_digest`, 같은 파일51행은 `sys.executable`의 `tarfile.extractall(filter="data")`를 사용한다. 현재 `python3`는3.9.6이며 실제 `host.sha()`를 임시 합성 파일로 호출하면 AttributeError, `extractall` signature에는 filter가 없다. 새 회귀25개는 이 실제 경로를 검사하지 않는다. 기존과 호환되는 스트리밍 hash/검증된 추출 helper를 재사용하거나 이미 있는 지원 interpreter를 명시적으로 고정해야 한다. 단순히 filter를 제거해 추출 보호를 없애면 안 된다. Python 신규 설치/업그레이드는 이번 결과로 승인하지 않는다.
2. **필수 Unix socket 양성 대조가 자체 권한에 막힘.** `guest.py:74`는 관리자 문맥에서 CLI 상태 루트를0755로 만들고 하위 tmp/log/logs/sessions/state만 worker UID22001에 넘긴다. `worker.py:50`은 그 루트의 `fixture.sock`에 bind하고54행에서 실패를 필수 양성 대조 누락으로 처리한다. 따라서 초안대로면 sandbox 시험에 도달하기 전에 멈춘다. 실제 register의 파일 배치 부분을 AST로 추출해 임시 경로와 chown 기록 대체로 검사한 결과 루트의 worker 소유권 지정0·비소유자 쓰기 불가였다. 쓰기 불가 임시 디렉터리에서 로컬 Unix bind도 EACCES를 확인했다. VM에서 실행한 재현은 아니다. 전용 worker 소유 socket 디렉터리를 CLI 상태의 deny 범위 아래 두고, 고정 config/표식의 관리자 소유권은 유지하는 국소 보완이 적합하다.

보고서가 이미 밝힌 watchdog 문제도 확인했다. `host.py:168`의 살아 있는 부모 + 만료된 `limit()` 조건은 dispose 호출 전 DeadlineExpired를 던진다. 같은 조건의 오프라인 대조에서 disposal0회였다. 실제 watchdog/시간 초과/late-write/cgroup/수집 연결이 검증되지 않았다는 인계의 한계를 유지한다.

이런 미실행 초안을 모두 완성시키는 것을 다음 실험의 선행 과업으로 잡지는 않는다. 기존 초안은 설계 참고로 보존하고, 다음 최소 시험에 필요한 코드만 선택한다. 재사용할 부분에는 실제 호출 경로의 국소 회귀를 둔다. 선택하지 않은 초안의 결함을 고치기 위한 별도 대형 보완 작업을 만들지 않는다.

## 권고와 아직 합의하지 않은 다음 범위

**C안은 후보로 유지하고, 검증 방법은 가설 우선으로 바꿀 것을 권고한다.** 이번에는 VM의 namespace/mount 실패도 성공도 관측하지 못했으므로 실행 아키텍처를 다시 바꿀 근거가 없다. 다만 총시간만90분에서180분 등으로 늘려 초안 전체를 완성하는 접근은 권하지 않는다.

다음 회차 제안은 **총60분, 새 VM 최대1개, 실제 sandbox payload 최대1개**의 호환성 관측이다. 이 예산/범위는 제안이며 아직 승인·실행되지 않았다.

- 먼저 실제 호스트 interpreter와 재사용 helper, 고정 공개 바이너리의 선택 추출/출처, VM 기동·외부 마감·실패 시 폐기 경로를 최소 크기로 확인한다. 비활성 전체 runner를 활성화하지 않는다.
- 고정 CLI를 전용 비특권 사용자·capability0·NNP·외부 통신 차단 상태로 직접 실행한다. source 읽기/쓰기·제공 자료 읽기가 가능한 작은 payload가 내부 sandbox를 실제로 통과하는지 한 번 확인한다. 명령/버전/hash/종료 상태와 원시 stderr를 남긴다. 정책 완화·새 패키지·다른 CLI로 바꾸지 않는다.
- 제출은 만들지 않고 호스트가 받은 유한 진단만 남긴다. 기존 deadline/VM 폐기 수단을 재사용하고 실패해도 소유 VM을 정리한다. 전체 제출 수집, 새 supervisor/봉인 프로토콜, 인증/socket/proc의 전체 부정 사례, timeout/wrapper 사망 주입, 새 VM2 반복은 이 호환성 시험에서 제외한다.
- 15분은 장애와 남은 비용을 점검하는 시점으로 바꾸고 완료 여부만으로 중단하지 않는다. 총60분은 강한 상한으로 두며45분부터 새 실험을 중단하고 정리/보고한다. 실제 권한·준비물 차단이나 안전한 폐기 경로 미확보 시에는 즉시 중단한다.
- payload가 실행되면 그 근거를 바탕으로 종료/수집 및 접근 경계 통합의 범위·예산을 다시 산정한다. 거부되면 최초 차단 근거를 검토한다. 둘 다 실제 자격 증명·모델 호출·S2 본 비교 준비 완료를 뜻하지 않는다.

지시 작성·개발 시간과 실제 준비/실행 시간을 분리 기록하고, 다음에는 추가된 코드량보다 핵심 가설에 관한 관측을 얻었는지로 투자 효과를 평가한다. 현재 PR #67은 중단 증거와 비활성 초안이며 병합을 보류한다. R11 unresolved·R12 기존 범위·production/live 거부·H-O/H-F 미검증을 유지한다. 다음 범위 합의 전 새 runtime이나 추가 예산을 자동 집행하지 않는다.
