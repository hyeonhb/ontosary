# 개발 지시문 · Vendure 부분 출고 첫 사용 검증 준비

공개 TypeScript 프로젝트를 처음 접한 개발자가 Ontosary로 업무 질문 하나를 조사해 짧은 기록을 남기고, 별도 agent가 그 기록을 다음 변경에 사용할 수 있는지 확인하려 합니다. 이번 작업은 **참가자가 바로 시작할 수 있는 자료와 독립적으로 결과를 판단할 근거를 준비해 리뷰에 인계하는 것**입니다. 자료 형식과 준비 방법은 개발 세션이 정해 주세요.

## 대상과 두 가지 요청

Vendure v3.5.0 Admin UI의 부분 출고를 사용합니다. 기준 리비전은 `534e6003534f74761e82de1b8c6061cba89945d1`입니다. 기존 공개 소스 준비물과 Ontosary README를 활용하고, 실제 시작에 필요한 버전·설정·명령을 확인해 주세요. [Vendure 소스 및 라이선스 기록](../../experiments/domain-model/SOURCE-NOTICE.md) · [Ontosary 시작 안내](../../README.md)

**작성자에게 전달할 업무 질문**

> 이미 일부 품목을 출고한 주문에서, 운영자가 추가 출고를 시작할 수 있는지와 각 품목을 몇 개까지 출고할 수 있는지는 각각 어떻게 결정되나요? 두 판단의 관계를 주문 예 하나와 함께 설명해 주세요. 다음 개발자가 직접 확인할 수 있도록 근거를 남겨 주세요.

**인계받는 agent에게만 전달할 후속 요청**

> 출고 창에서 어느 품목도 출고할 수 없을 때 운영자에게 이유를 안내하려고 합니다. 인계 기록과 소스를 읽고 어디를 확인하고 무엇을 바꿀지 제안해 주세요. 그대로 보존할 동작과 이를 확인할 회귀 사례 한 건을 제시해 주세요.

## 역할과 입력

- **작성자**는 해당 코드를 작성하거나 유지보수하지 않았고 이 과업의 답을 미리 보지 않은 임의의 TypeScript 개발자 한 명을 후보로 합니다. 특정인 섭외 없이 준비를 끝낼 수 있습니다. 실행 시 Vendure·Ontosary 사용 경험을 짧게 기록합니다. 작성자는 공개 사용 안내, 대상 소스, 평소 IDE·검색과 Ontosary CLI를 사용합니다. 자유 형식의 짧은 기록에 관계와 적용 조건, 파일·심볼, 사례, 확인하지 못한 점을 남길 수 있게 해 주세요. 코드 관찰과 업무 의도에 대한 추정을 구분하며 조직의 정책 승인은 미확인으로 둡니다.
- **인계받는 agent**는 새 세션에서 같은 리비전, 작성자의 완성된 기록, 후속 요청을 받습니다. 작성 대화나 구두 보충 없이 근거를 확인하고 변경 제안을 제출하도록 준비합니다. 기록에서 활용한 내용과 소스에서 추가로 찾아야 했던 내용을 짧게 남깁니다. 패치 구현은 후속 요청의 범위 밖입니다.
- **진행·검토자**는 참가 전에 고정 소스에서 두 판단의 근거, 둘을 구별할 주문 사례 하나, 후속 제안이 보존해야 할 동작을 확인합니다. 동등한 다른 근거와 변경 제안도 인정할 수 있게 판단 이유를 남깁니다. 참가자에게는 각자 필요한 입력만 전달합니다. 이 지시문 전체, 내부 평가 메모, 답을 암시하는 파일·심볼 목록은 참가자용 시작 안내에서 제외해 주세요.

사람을 구하지 못하면 작성자 미배정으로 인계해도 준비 완료입니다. 이후 작성자 역할을 새 agent로 대체하기로 결정한다면 두 독립 세션의 **대리 검증**으로 표시합니다. 그 기록으로 사람의 첫 사용성·사람 소요 시간·업무 승인을 판정할 수 있는 항목은 없습니다.

## 준비할 관찰과 판정

| 관찰할 것 | 나중에 성공을 판단할 근거 |
|---|---|
| 처음 쓰는 개발자가 기록을 만들 수 있는가 | 답을 가리키는 도움 없이 두 판단과 그 관계를 기록하고, 검토자가 같은 리비전에서 핵심 설명과 사례를 다시 확인할 수 있습니다. 도움을 받았다면 어느 단계까지 독립적으로 진행했는지 남깁니다. |
| 다른 agent가 기록을 변경에 쓸 수 있는가 | 후속 요청에 맞는 변경 위치, 보존할 동작과 회귀 사례를 원문 근거로 설명합니다. 기록이 실제로 쓰인 지점과 처음부터 다시 조사한 부분을 구분합니다. |
| Ontosary가 무엇을 도왔는가 | 핵심 근거를 어디서 처음 찾았는지, CLI 결과나 FCA 후보가 연결을 찾거나 확인하는 데 어떤 역할을 했는지, 무관한 후보 검토에 어떤 노력이 들었는지 남깁니다. 검색만으로 인계에 성공하거나 FCA의 기여가 관찰되지 않은 경우도 그대로 판정합니다. |

비용은 준비자가 미리 해 준 환경 설정, 작성자의 설정·조사·기록 시간, 진행자의 도움, agent의 추가 탐색으로 나눠 적을 수 있으면 충분합니다. 작성자 45~60분과 인계 agent 한 세션은 향후 진행을 위한 계획값입니다. 이번 준비에서는 시간을 예측값으로 채워 넣지 마세요.

## 완료와 인계

1. 작성자용 시작 안내와 후속 agent용 요청을 각각 전달 가능한 상태로 만들고, 참가자에게 보일 실제 자료에서 정답 단서와 이전 세션 기록이 섞이지 않았는지 한 번 확인해 주세요.
2. 준비자가 대상 리비전과 분석 범위를 확인하고 공개 명령으로 시작할 수 있는지 점검해 주세요. 재사용한 cache, 사전 빌드, 별도 설정, 미지원·상한·오류가 있으면 그대로 기록합니다. 막히면 공개 경로에서 어디까지 가능했는지와 필요한 최소 조치를 인계해 주세요. 이를 해결하기 위한 새 실행 환경이나 제품 기능 구축은 별도 판단 대상입니다.
3. 결과 PR에는 참가자 자료, 검토자용 소스 근거와 판정 기준, 시작 점검의 실제 결과, 남은 제약을 연결해 주세요. **자료 준비 상태와 참가 결과는 별도로 표시**하고 첫 사용·인계·도구 기여 판정은 실행 전까지 미측정으로 둡니다. 이번 작업은 준비 결과의 리뷰에서 끝납니다. 실제 참가, 참가 모델 호출, 기존 배송비 취소 S2 A/B/C 재실행은 이후 별도로 결정합니다.
