# R20 보완 개발 지시 — 목적과 완료 기준 중심

2026-11-18. [개발 자율성 합의](../DECISIONS.md#adr-059--목적과-완료-기준-중심의-개발-지시--2026-11-18)에 따라 작성한다. 이번 작업에는 이 문서를 적용한다. [이전 지시](2026-11-18-s2-smoke-cleanup-budget-instructions.md)는 이력으로 보존하며, 거기에 적힌 구현 순서·출력 처리 방식·세부 테스트 구성은 더 이상 필수 절차가 아니다.

## 목적과 배경

S2는 변경 전 도메인 모델이 agent의 수정 작업에 도움이 되는지 검증하는 단계다. 지금 환경 보완의 목적은 실패한 실행의 자원을 확실히 정리해 다음 검증을 이어갈 수 있게 하는 것이다. 전체 실행기를 새로 설계하는 작업은 아니다.

[독립 리뷰](2026-11-18-s2-vm-cli-smoke-independent-review.md)의 R20은 일반 진단 예산이 소진되면 정리용 stop/delete도 출력 때문에 종료되는 결함이다. PR #70의 `2008351`에서 실제 정리 함수와 가짜 외부 명령으로 재현했다. 당시 실제 VM은 정상 폐기됐지만, 실패 시 로그가 많아지는 경우에도 같은 보장이 필요하다.

**진단 용량 소진이나 기록 실패가 소유 자원의 정리를 막지 않도록 보완해 주세요. 정리 결과는 확인한 근거에 맞게 보고해야 합니다.**

## 범위와 개발 자율성

대상은 PR #70의 smoke 정리 경로와 관련 검증이다. `experiments/domain-model/s2/trial/vm-cli-smoke/`가 결함을 확인한 위치이며, 수정 파일·함수·자료구조·구현 및 검증 순서는 개발 세션이 선택한다. 범위 내 국소 수정은 별도 승인 없이 진행한다.

기존 구조 안에서 해결하고 제품·공유 runtime·평가 의미·준비물·guest 권한은 변경하지 않는다. 새 VM, 실제 limactl 제어, CLI binary 실행, trace, 정책 변경, 자격 증명 전달, provider/model 호출과 본 비교는 이번 범위에 없다. 검증은 로컬 대체 명령과 저장 증거로 수행한다. EROFS 원인 해결이나 C안 전체 통합은 별도 작업이다.

## 필요한 결과와 완료 기준

- 진단 예산이 충분하거나 소진된 경우, 진단 조회·저장에 실패한 경우 모두 정리 경로가 필요한 소유 자원 정리를 계속 수행한다. 호출 여부만으로 통과시키지 않고, 정상 동작하는 대체 외부 명령이 실제 완료해 자원 상태를 바꾸는 근거를 보여준다.
- 외부 정리 명령 자체가 실패하거나 멈춰도 후속으로 가능한 정리를 계속하고 유한 시간 안에 종료한다. 기존 소유권 확인과 시간·메모리·저장 상한을 유지한다. 로그 한도 확대나 무제한 출력 수집으로 문제를 우회하지 않는다. 일반 실험 명령의 기존 출력 초과 중단 동작도 유지한다.
- 정리 실행, 진단 기록, 최종 자원 상태를 구분한다. 조회 실패·잘린 응답·timeout·파싱 불능을 자원 부재로 해석하지 않는다. 부재를 확인하지 못하면 정리 완료로 보고하지 않으며, 앞선 오류 뒤 부재를 확인했다면 두 사실을 함께 남긴다.
- 원래 R20 반례의 수정 전 실패와 수정 후 통과를 보여주고, 위 실패 조건 및 정상 경로를 포함하는 회귀로 결과를 입증한다. 구체적인 fixture와 테스트 분할은 자율적으로 설계한다. 관련 Python 회귀와 `pnpm check`를 통과한다.
- 과거 실행 증거·freeze·원문·코드 식별자는 보존한다. 당시 코드에 대응하는 검증으로 기존 관측의 불변을 확인하고 새 검증 결과는 별도로 기록한다. 현재 코드를 과거 실행 코드로 대체하거나 hash 불일치를 무시하지 않는다.

## 시간과 이슈 공유

기존 45분 상한(읽기·수정·검사·보고 포함)을 유지한다. 착수 시 남은 불확실성과 예상 작업량을 판단하고, 이 범위로 완료하기 어렵다고 보이면 원인·현재 결과·대안을 공유한다. 새 단계별 시간 gate나 재시도 횟수는 추가하지 않는다. 상한에 도달하면 검증된 부분과 미완료를 인계하며, 시간 확대나 실제 실행으로 자동 전환하지 않는다.

범위 안의 구현 문제는 스스로 수정한다. 주요 아키텍처·범위·비용·권한 변경이 필요할 때 논의하며, 보고는 의미 있는 결과나 완료 전망에 영향을 주는 장애 중심으로 한다.

## 인계와 후속 판단

보고서에는 해결 방식과 이유, 반례 및 회귀 결과, 검증한 코드 식별자, 남은 한계와 소요 시간을 남긴다. PROGRESS와 필요한 관련 문서를 실제 결과에 맞게 갱신한다. 기존 저장소 절차에 따라 PR #70을 갱신하되 최신 main과의 기준을 명시하고, **독립 보완 리뷰 전에는 병합하지 않는다.** PR #67은 별도로 유지한다.

완료 판정은 위 결과와 구현 품질을 기준으로 한다. 이 작업의 완료는 R20 보완이며 EROFS 해결·R11 완료·C안 채택·모델 효용 입증을 뜻하지 않는다. 후속 실제 시험과 본 비교는 결과 리뷰 뒤 결정한다.
