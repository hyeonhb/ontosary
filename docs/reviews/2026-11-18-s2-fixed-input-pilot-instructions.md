# S2 개발 지시 · Vendure 주문 취소 고정 입력 패치 파일럿

**변경 전 도메인 지식을 제공했을 때 같은 모델이 더 정확한 주문 취소 패치를 만드는지 확인해 주세요.** 기존 입력과 평가기를 재사용해 A/B/C를 각각 독립 세션에서 한 번 실행하고 첫 제출을 채점합니다. 세 패치의 차이를 보고 도구를 갖춘 본 비교에 투자할지 판단하는 것이 목적입니다. 개발 세션은 패킷 구성·실행·채점 방법을 선택합니다. 준비부터 결과 보고까지 1.5~3시간은 계획용 추정입니다. loopback 진단은 보류합니다.

## 첫 호출 전에 고정할 것

공통 업무 요구는 [공개 과업과 안내](../../experiments/domain-model/s2/trial/task.ts)의 현행 버전을 사용합니다. 취소 사유의 공백 제거, 유효하지 않은 취소의 무요청 종료, 혼합 흐름의 후속 환불 중단, 환불 전용 동작과 원래 환불 사유 보존을 포함합니다. 공개된 수정 범위와 지원 문법은 유지합니다. 파일을 열거나 셸 검사를 하라는 기존 작업공간 안내는 세 조건에 동일하게 **제공된 텍스트만 사용해 기준 소스에 적용할 단일 패치를 반환**하는 안내로 바꿉니다. 이 개발 지시문 자체에는 평가자용 정보가 있으므로 참가 모델에는 공개 입력만 전달합니다.

| 조건 | 모든 세션이 받는 동일 입력 | 조건별 추가 입력 |
| --- | --- | --- |
| A | 업무 요구, 공개 제약, 경로가 표시된 변경 전 소스, 제출 형식 | 없음 |
| B | 동일 | 변경 전 구조화 도메인 모델 뷰 |
| C | 동일 | B와 같은 지식을 설명하는 서술형 문서와 메타데이터 부록 |

[11월 10일 준비본](../../experiments/domain-model/s2/results/2026-11-10-trial-preparation)을 기준으로 세 패킷을 먼저 완성합니다. 공통 소스는 공개된 업무 범위에서 재현 가능한 선정 규칙으로 고릅니다. 숨긴 사례나 정답 패치의 수정 파일 목록으로 선택하면 탐색 답을 미리 제공하게 됩니다. 세 패킷에는 동일한 소스 본문과 경로를 넣고 제외 범위를 기록합니다. B/C를 줄일 필요가 있으면 같은 개념·관계·근거·검토 상태 단위로 줄이고 C의 대응 부록도 포함합니다. 양쪽에 새 취소 정책이나 풀이 힌트가 들어가지 않았는지 확인합니다. 공통 본문과 패킷의 해시, 소스 revision, B/C 대응 범위와 크기를 기록하고 가장 긴 입력도 출력 여유와 함께 문맥에 들어가는지 첫 호출 전에 확인합니다.

## 세 번의 독립 실행

동일한 모델·reasoning 설정과 시간·출력 예산으로 새 세션 세 개를 사용합니다. 세션은 지정한 패킷과 동일한 공통 지시만 받고 한 번씩 답합니다. 대화 상속·공유 메모리·저장소 접근·검색·셸·비공개 평가기·다른 세션 결과가 없는 텍스트 실행 경로를 사용합니다. 참가 모델의 도구는 실행 설정에서 차단합니다. 개발·리뷰 대화에서 과업을 이미 본 agent는 참가자가 될 수 없습니다. 기존에 이용 가능한 승인된 모델 접속 경로를 사용하고, 새 자격 증명이나 유료 인프라가 필요하면 호출 전에 범위를 논의합니다.

중립 실행 ID, 배정 순서, 모델 식별자·설정, 실제 입력·원응답, 관측 가능한 시간·usage를 보존합니다. 조건당 첫 응답 하나가 제출입니다. 사람이 패치를 보정하거나 평가 결과로 재질문하지 않습니다. 응답 누락·중단도 예정된 세 실행의 분모에 남기고 모르는 사용량은 미상으로 둡니다. 입력에 대한 도움 없이 모델 응답 3개를 봉인한 뒤 채점합니다.

## 외부 채점과 완료 기준

- 모델 호출 전에 평가자 측에서 고정 Vendure 원본과 참조 제출로 채점 경로를 점검합니다. 기존 교정 기대값은 원본 타입 통과·동작 22/52(기존 동작 16/16, 변경 요구 6/36), 참조 타입 통과·52/52입니다. 차이가 있으면 입력·평가 환경부터 확인합니다. [기존 교정 기록](2026-11-11-s2-linux-evaluation.md)
- 패치 형식과 추출 규칙을 세 조건에 동일하게 적용합니다. 조건마다 새 원본 전체 복사본에 패치를 기계적으로 적용하고 그 결과 전체 소스를 채점합니다. 경로 이탈·특수 파일은 거부하고 삭제·추가·수정은 그대로 반영합니다. 적용 불가와 평가기 미지원, 환경 오류, 타입 실패, 동작 실패를 구분합니다. 제출 코드 실행은 평가자 측 격리 환경에서 수행합니다.
- 기존 [complete-root 평가 진입점](../../experiments/domain-model/s2/evaluation/run.ts)과 v4 평가 기준을 사용합니다. 계약은 전체 제출 루트·준비된 환경 루트·새 출력 JSON입니다. 결과에 evaluatorId, 제출 지문, 타입 검사, 동작 검사, sourceBinding, overall을 남깁니다. 세션에 주는 입력은 축소할 수 있지만 **채점 대상은 패치를 적용한 전체 기준 소스**입니다. 이번 결과는 별도 pilot 기록으로 보관하고 본 비교의 실행 차단과 결과 필드는 유지합니다.
- 결과 보고서 첫 표에서 세 조건의 패치 적용 여부, 타입 결과, 기존 동작 16개·변경 요구 36개의 통과 수, 전체 판정, 시간·usage를 한눈에 비교할 수 있게 합니다. 미실행 사례는 미실행으로 표시합니다. 실제로 차이가 난 업무 동작 한두 가지를 패치와 근거에 연결하고, 제공 자료에서 가능한 설명과 모델이 실제로 그 자료를 사용했다는 증거를 구별합니다.

A/B는 지식 추가 효과, B/C는 정보가 대응되는 범위에서 표현 방식의 차이를 살펴봅니다. 표본은 조건별 패치 한 개이며 52개 사례는 그 패치의 검사 항목입니다. 공통 소스 선정·입력 길이·B/C 의미 대응·모델 변동을 고려해 다음 실험에 투자할 이유를 제시합니다. 파일 탐색 효율과 FCA의 모델 구축 기여는 이번 측정 범위 밖입니다.

원시 근거와 보고서를 새 파일럿 경로에 남기고 PROGRESS에 실제 실행·채점 분모를 기록해 주세요. 세 조건의 점수와 실패를 포함한 인계가 완료 기준입니다. 입력 구성이나 채점 경로 자체에 문제가 있어 비교가 성립하지 않으면 해당 근거와 영향을 보고합니다. 저장소 검사 후 결과 PR을 독립 리뷰에 인계합니다.
