# TypeScript 4.9.4 명시 선택 보완 독립 리뷰

[PR #135](https://github.com/hyeonhb/ontosary/pull/135)의 `2f038e9`에서 이전 리뷰의 두 문제를 재검산하고 병합했다. 공개 CLI의 `--typescript-version 4.9.4` 선택을 지원한다. 기본 분석 버전은 5.9.3이다. [이전 반례](2026-11-28-typescript-494-independent-review.md) · [보완 결과와 재현 명령](2026-11-28-typescript-494-soundness-fix.md)

- **숫자 enum.** 일반 `number`에 담긴 99를 두 컴파일러 모두 허용하고, 예제의 두 함수는 `false`와 `true`를 반환한다. 기본·명시적 5.9.3·명시적 4.9.4 모두 비교 결과는 종료 2, `Unsupported`, 열거 0회였다. 별도로 숫자 enum을 객체 필드에 넣은 예에서도 함수의 비교와 if 조건 정규화가 같은 기준으로 거부됐다. 문자열 enum 양성 대조는 세 경로에서 두 값을 평가해 동치였다.
- **컴파일러 로드 실패.** 빌드 결과와 4.9.4 의존성만 둔 별도 설치에서 버전 생략과 5.9.3 명시 모두 종료 1, 빈 stdout, stderr 오류 JSON 한 건을 확인했다. 이때 요청 버전은 5.9.3이고 사용 버전은 null이었다. 같은 설치에서 명시한 4.9.4는 실제로 선택되어 정상 입력을 분석했다.
- **실제 프로젝트.** 고정 Excalidraw 사본에서 두 공개 CLI scan을 다시 실행해 소스·설정·lockfile과 결과를 기존 검산기로 대조했다. 4.9.4는 종료 0·진단 0개, 5.9.3은 종료 1·기존과 같은 진단 7개였다. 두 버전 모두 구현 파일 370개·함수 4,475개, 동결한 두 심볼의 시작·끝 위치가 일치했다.

`pnpm check`는 308개 통과·기존 Vendure 준비 캐시 의존 5개 건너뜀, `pnpm experiment`는 4/4였다. 다음 순위는 화살표 후속 변경에서 동결 기록의 효용을 측정할 조건과 예산을 정하는 일이다.
