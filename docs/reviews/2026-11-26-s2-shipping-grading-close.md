## 같은 제출에서 달라진 판정

지난 리뷰의 JSON에서 패치 원문을 꺼내 지문을 확인하고, 변경 전 Vendure의 새 작업 사본에 단일 제출 명령으로 적용했다. 적용 후 Git 트리가 이전과 같았고, 채점 결과는 이번 보관본과 바이트 단위로 일치했다. 종전 **4통과·0실패·2판정 불가**가 **4통과·2실패·0판정 불가**로 바뀌었다. [이전 독립 반례](evidence/2026-11-26-shipping-grading-inclusive-only.json) · [새 채점 결과](../../experiments/domain-model/s2/results/2026-11-26-shipping-inclusive-only/grade.json)

세금 별도 전체 취소 두 건의 기대값은 모두 0이었다. 주문 저장 시점과 메서드 반환 시점에 관측한 네 값은 모두 `1000 / 1200 / 1000 / 1200`이었다. 순서대로 세전·세후 배송비와 세전·세후 주문 합계다. 반대 방향도 확인했다. 업스트림 정상 수정에 일부 취소 때 금액이 그대로인 배송 행을 다시 저장하는 호출을 추가해 채점하니 여섯 건 모두 통과했다. 이제 저장 호출 여부를 진단에 남기면서 관측한 업무 결과로 점수를 매긴다. [관측 코드](../../experiments/domain-model/s2/trial/angular-shipping/observe.mjs)

## 기존 대조와 다음 결정

새 경로에서 13개 제출을 재현했다. 기존 12개는 새로 기록하는 배송 행 저장 여부를 제외한 모든 필드가 이전 결과와 같았다. 원본·부분 수정·업스트림·외부 헬퍼의 통과 수는 **4/6·4/6·6/6·6/6**이었다. 잘못된 금액을 저장한 R26 반례와 상품 수량을 줄이지 않은 R27 반례는 각각 6건 모두 업무 실패였다. 관측하지 못한 경로와 대역 필드 부재는 판정 불가로, 적용할 수 없는 패치는 사례 실행 0건으로 유지됐다. 기존 선정 재생 출력도 보관본과 일치했다. PR head에서 `pnpm check`의 테스트 304개와 예제 빌드, `pnpm experiment`의 비교 4개가 통과했다. [재현 명령과 보관 결과 대조 방법](2026-11-26-s2-shipping-inclusive-only-grading.md#재현)

다음 결정은 A/B/C 조건별 한 번, 총 세 독립 세션의 실행과 예산이다. 이번 결과가 확인한 범위는 메모리 저장소에 전달된 주문 금액과 취소 메서드의 반환 결과까지다. 실제 DB 재조회와 참가 에이전트의 수정 성과는 아직 측정하지 않았다. 참가 호출은 0회다.
