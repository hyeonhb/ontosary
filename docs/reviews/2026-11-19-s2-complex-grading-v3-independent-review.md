# S2 복합 수정 채점 v3 독립 리뷰

2026-11-19. PR #85의 `89f3c6d`를 검증했다. **R21과 R22를 닫고 고정 입력 A/B/C 비교를 실행할지 결정할 수 있다.** 수량 편집 가능 여부가 성공 점수에 반영되고, 직전 리뷰에서 달리 집계됐던 오류들은 같은 발생 원인에 같은 판정을 받는다. 평가 과업 참가 호출은 0/18이다. [준비 보고서](2026-11-19-s2-complex-task-preparation.md) · [직전 독립 리뷰](2026-11-19-s2-complex-grading-v2-independent-review.md)

## 근거

직전 리뷰의 독립 반례 세 패치와 v3 회귀용 패치의 SHA-256이 일치했다. 새 작업 경로에서 전체 Vendure 소스로 원본·참조·부분 패치 9건, 봉인된 예비 A 1건, 오류와 비용 집계 대조 12건을 다시 채점했다. 사례별 관측과 합성 비용표가 동결 기록과 일치했다. [회귀 대조 원시 기록](../../experiments/domain-model/s2/results/2026-11-19-complex-grading-v3/regressions/)

| 독립 확인 항목 | v3 재현 결과 | 비교에 주는 의미 |
| --- | --- | --- |
| R21 수량 편집과 취소 체크박스 | 표시 조건을 뒤집으면 6/8, 참조는 8/8 | 잔여량이 있는 항목을 편집할 수 없는 제출은 완전 성공에서 제외된다. |
| 번역 서비스가 빠진 평가 대역의 오류를 새 오류로 감싸 전달 | 원래 TypeError를 기록하고 귀속 미상으로 처리 | 사용량과 예정 분모는 보존하고 해당 조건 간 효과 판단을 보류한다. |
| 제출이 유효 수량에서 직접 던진 오류를 감싸 전달 | 원래 RangeError와 제출 위치를 기록하고 업무 실패로 집계 | 실패에 쓴 비용도 추가 성공당 비용 비교에 포함된다. |
| 동일한 Subscriber의 일반·선택·대괄호 오류 호출 | 세 표기의 사례별 관측·오류 값·제출 위치와 비용 판정이 일치 | 같은 실패에 대해 작성 방식만으로 조건 간 비교 가능 여부가 달라지지 않는다. |
| 선택 호출의 대상 메서드가 없음 | 인자를 평가하지 않고 화면 동기화 24/24 통과 | 채점용 계측이 원래 생략되는 오류를 발생시키지 않는다. |

별도 패치 세 개도 확인했다. 번역 대역 오류와 제출 오류에 중간 오류를 한 겹씩 더 넣어도 각각 귀속 미상과 업무 실패로 남았다. 메서드가 없는 Subscriber에 대괄호 접근과 선택 호출을 함께 쓴 경우에도 24/24였다. 원인을 확인하기 어려운 입력은 효과 판단을 보류하는 기존 계약을 유지한다.

새로 조립한 입력과 도구 목록을 로컬 요청으로 확인했다. v1 계약과 대조해 배정·예산·참가 입력이 같고 v3 평가기 지문만 바뀐 것도 확인했다. B/C의 구조 대응 1,511개, 소스 인용 30개, 비용 집계 회귀 3개, 저장소 타입 검사·304개 테스트·예제 빌드와 기존 실험 비교 4개가 통과했다. [동결 계약](../../experiments/domain-model/s2/results/2026-11-19-complex-grading-v3/contract.json)

## 다음 결정

동결한 두 가지 실험용 클라이언트 정책을 채택하는 것을 권한다. 수량 과업은 주문 당시 수량에서 모든 결제의 해당 항목에 대한 비실패 환불 수량을 뺀다. 화면 과업은 실제 변경 요청을 보냈다면 거절만 돌아온 경우에도 모든 결과가 결정된 뒤 한 번 동기화하고, 대화상자를 닫기만 하면 조용히 끝낸다. 두 조건 모두 참가자에게 공개되며, 변경 전 지식이 기존 동작을 지키며 구현하는 데 도움이 되는지가 비교 대상이다. B/C의 사람에 의한 업무 의미 동등성 확인은 남아 있다. [수량 요구](../../experiments/domain-model/s2/trial/complex/public/quantity.md) · [동기화 요구](../../experiments/domain-model/s2/trial/complex/public/refresh.md)

두 과업 × 세 조건 × 독립 반복 3회로 총 18회다. 예상 입력은 984,000~1,092,000토큰, 출력은 3,600~72,000토큰이며 토큰 한도는 실제 사용량으로 사후 판정한다. 성공은 첫 제출의 완전 통과로 센다. 추가 성공당 비용은 비교가 가능하고 A보다 성공이 늘었을 때만 계산한다. 회귀 대조의 비용은 합성값이며 아직 B/C의 실제 추가 성공이나 비용은 관측되지 않았다. 실행 예산과 업무 가정의 최종 결정은 사용자에게 남긴다.
