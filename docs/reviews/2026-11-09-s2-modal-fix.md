## 연결 순서와 필드 소유권

`behavior.ts`는 부모 `cancelOrRefund`부터 실행한다. 부모 fixture에 dialog가 필요한 id/active/payments/state/lines를 한 번 제공한다. 기존 dialog 사전 실행과 `fromComponent: () => of(returned)`는 제거했다. 실제 `fromComponent(component, options)`가 `modal.ts`로 이어진다.

`execute.ts`의 작은 component 조회는 기존 load/제외 seam 검사를 거친 constructor를 반환한다. modal은 같은 executor에서 로드한 두 constructor와 참조가 같은지 확인한다. 이름이 같은 임의 함수나 시나리오 mode로 정상 component를 대신하지 않는다. 실제 선택된 component에 맞는 사용자 상태를 준비하고, 생성도 기존 executor 경로를 사용하므로 파일 hash/sourceBinding 추적은 유지한다.

locals의 order는 부모 소유다. id/active/lines의 형식만 확인하고 객체·업무 값을 복구하지 않는다. 사용자 reason/line 선택·cancelAll·선택 payment/배송 상태는 fixture 소유이고 order/resolveWith와 충돌하면 미지원이다. 이 상태는 미실행 UI 초기화·계산의 명시적 대역이며 constructor/field 초기화·ngOnInit/HTML/화면 전체를 검증한 것은 아니다. 요청 기대값은 기존 독립 fixture/계약을 유지하며 실제 잘못된 locals로 기대값을 다시 계산하지 않는다.

## Observable·실행 경계

호출 시 options/locals의 관찰을 복사하고, 구독 시 해당 dialog를 만든다. 제출 select/cancel을 한 번 호출하고 실제 resolve 시 해당 구독에 next(value)→complete를 전달한다. 호출→구독→행동→resolve→next→complete→행동 반환 순서를 기록한다. 실제 pinned RxJS를 사용하며 대역은 payload/trim/취소·환불 분기를 작성하지 않는다.

비API 사례는1modal·1구독·1동기 resolve를 지원한다. undefined 닫기는 실제 undefined를 전달하며 trace에는 `{$type:"undefined"}`로 남긴다. 미해결 상태의 resolveCount=0/전달0과 다르다. 미해결·다중 resolve·재구독/미구독·추가 modal, 알 수 없는 constructor/잘못된 locals 형식/미지원 옵션은 호출별 사유를 가진 unsupported다. 미해결에서 임의 dismiss 값을 만들지 않는다. 각 호출의 상태를 독립 소유하며 자체 fixture에서는 상한2를 명시해 연속된 다른 입력도 확인했다. 생산 교정의 상한은1이다.

이 계약은 실제 Angular overlay Promise/뷰 lifecycle·비동기 네트워크를 구현했다는 뜻이 아니다. 기존 Promise/async/미검토 operator/제외 seam 제한을 유지한다. [원문 대응](../../experiments/domain-model/s2/verification/2026-11-09-modal-fix/modal-upstream-source.json)은 원래 ModalService의 next/complete와 ModalDialogComponent.onCreate의 resolveWith/locals 전달 구간·hash를 보존한다. 동기화 대역의 한계와 원문 충실성 최종 검토는 별개다.
