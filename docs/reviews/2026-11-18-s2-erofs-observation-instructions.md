# S2 EROFS 실패 경로 관측과 조건부 최소 조치

2026-11-18. [정적 진단 리뷰](2026-11-18-s2-erofs-diagnosis-independent-review.md)에 이어 실제 실패 지점을 확인하고, 가설이 맞으면 국소 조치의 효과까지 확인한다. 이번 문서는 개발 세션에 전달할 지시이며 작성 세션에서 시험을 실행하지 않는다.

## 목적

S2의 모델 효용 검증을 이어가기 위해 고정 CLI의 시작을 막는 EROFS 원인을 확인한다. 선두 후보는 helper가 `canonical(/tmp)/codex-daemon-22002`를 생성하는 작업이며, 아직 실패 syscall은 관측하지 못했다.

**같은 실행 조건에서 실제 실패 경로·연산·errno를 확인해 주세요. 이 디렉터리 생성이 원인으로 확인되면, 관리자가 해당 디렉터리만 미리 준비하는 최소 조치를 적용해 같은 오류를 통과하는지 대조해 주세요.** 새로운 실행기나 본 비교 환경 전체를 완성하는 작업은 아니다.

## 범위와 개발 자율성

기존 공개 준비물·고정 바이너리와 R20 보완 정리 경로를 재사용한다. 일회성 VM 한 개에서 원래 조건의 기준 관측과, 아래 조건을 충족할 때 최소 조치 후 대조를 수행한다. native sandbox 실행은 기준 한 회·조건부 대조 한 회를 범위로 잡는다. 관측 준비와 로컬 검증 순서, 도구, 구현 파일과 자료구조는 개발 세션이 선택한다. 시험 분모는 위 두 질문에 한정하고 성공할 때까지 설정을 바꿔 반복하지 않는다.

strace는 사용할 수 있는 수단 중 하나다. 기존 도구와 guest 관리 권한으로 필요한 관측을 얻고, worker의 UID·capability·NNP·외부 네트워크 차단·내부 profile은 유지한다. tracer가 실행 조건에 주는 영향도 설명한다. 도구 부재나 관측 제약을 해결하려고 새 이미지·범용 추적 기반을 만들거나 권한을 추가하지 않는다.

기준에서는 원래 argv·환경·작업 디렉터리·서비스 파일 접근 정책을 유지한다. 조건부 대조의 허용 변경은 확인된 daemon 디렉터리의 사전 준비뿐이다. `/tmp` 전체 쓰기 허용, ProtectSystem 해제, 별도 writable 경로 추가, CLI 업데이트와 내부 sandbox 우회는 포함하지 않는다. 실제 자격 증명·provider/model 호출·Vendure 통합·본 비교도 이번 범위가 아니다.

## 필요한 결과와 조건부 조치

- **기준 관측:** CLI와 helper의 연결, 실패 syscall의 경로·연산·errno·순서를 확인한다. 동일 서비스의 관련 mount 상태와 대상 경로의 사전 존재·소유자·권한을 연결해 설명한다. 원문과 관측 누락·절단 여부를 남긴다. 특정 tracer나 출력 형식을 강제하지 않는다.
- **조치 조건:** 관측이 예상 daemon 경로 생성의 EROFS를 뒷받침하고 경로가 소유 VM 안의 예상 대상임을 확인했을 때만, guest 관리자가 그 디렉터리를 worker UID22002 소유·0700으로 준비한다. 기존 경로가 symlink이거나 예상과 다른 소유권/종류라면 덮어쓰거나 권한을 바꾸지 말고 근거를 남긴다. 그 밖의 경로/연산이 원인이거나 관측이 불완전하면 이 조치를 적용하지 않는다.
- **대조:** 같은 CLI 입력과 서비스 정책으로 원래 실패 지점을 통과하는지 확인한다. 사전 준비 외의 상태 차이가 판단에 영향을 주는지 설명하고, 새 오류가 나오면 원래 EROFS 해소와 다음 차단을 구분한다. payload가 완료됐다면 기존 smoke의 읽기·쓰기·결과 기준으로 확인한다. 어떤 경우든 전체 격리 검증이나 모델 효용으로 확대 해석하지 않는다.
- **종료와 근거 보존:** 성공·실패·관측 불능 모두에서 소유 VM과 프로세스를 정리하고 그 결과를 확인한다. 시간·메모리·출력은 유한하게 관리하며 진단 저장 실패가 정리를 막지 않아야 한다. 원래 freeze와 증거는 보존하고 새 코드·설정·결과의 식별 근거를 별도로 남긴다.

기준 오류가 재현되지 않거나 tracer 부착/관측이 실패한 경우는 미확정으로 인계한다. 다른 원인이 확인되면 그 원인과 다음 선택지를 보고한다. 추가 권한, 다른 설정 변경 또는 세 번째 native 실행이 필요하면 현재 결과로 멈추고 논의한다. 관측 준비의 국소 오류 수정과 로컬 검증은 범위 안에서 자율적으로 진행한다.

## 시간·검증·인계

준비·관측·대조·정리·보고까지 **60~90분을 참고 예상**으로 제시한다. 확정된 시간 상한이나 단계별 gate는 아니며, 착수 시 개발 세션이 난이도와 준비물 상태를 보고 추정을 조정해 알린다. 완료 전망이 크게 달라지거나 환경 구축이 새 작업으로 커지면 원인·현재 근거·선택지를 먼저 공유한다. 각 외부 명령과 시험에는 유한 마감을 적용하고 정리 시간을 확보한다.

필요한 로컬 회귀와 `pnpm check`를 수행한다. 관측/정리 코드를 바꾸었다면 실제 변경한 오류 경로를 검증하고, R20의 보장을 유지한다. 바꾸지 않은 계층의 실험을 형식적으로 반복할 필요는 없다.

보고서에는 확인된 원인 또는 미확정 이유, 실제 적용한 차이, 기준/대조 결과, 남은 차단과 정리 결과를 먼저 제시한다. 실제 실행 횟수·검증한 코드/바이너리·원시 근거 위치·소요 시간과 한계를 함께 남긴다. PROGRESS 등 관련 문서를 실제 결과로 갱신하고 저장소 절차대로 새 PR로 인계하되, **실험 결과와 변경은 독립 리뷰 전 병합하지 않는다.** PR #67은 별도 보류한다.

완료는 원인과 최소 조치 효과를 판단할 근거 및 자원 정리가 확보된 상태다. 가설 기각·다음 오류·관측 불능도 정직하게 인계할 수 있으며 성공으로 포장하지 않는다. 후속 권한 변경·C안 채택·인증/model·본 비교는 결과 리뷰 뒤 결정한다.
