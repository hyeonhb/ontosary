# S2 보완 독립 리뷰 · 배송비 취소 결과의 판정

**R26은 종료한다. R27의 원래 수량 반례도 해결됐다.** 다만 정상 반환한 제출이 세금 별도 주문의 배송비를 전혀 취소하지 않아도, 그 금액을 확인하기 전에 채점이 끝나는 경로가 남았다. PR #107 병합과 참가 실행은 이 사례의 판정을 확인한 뒤 결정한다. [검토한 보완 보고서](https://github.com/hyeonhb/ontosary/blob/3858a32/docs/reviews/2026-11-26-s2-shipping-grading-fix.md)

## 보완 결과

PR head `3858a32`에서 Python 3.12.10과 Node 22.19.0으로 새 작업 사본을 생성했다. 12개 제출의 통합 결과가 보관본과 바이트 단위로 일치했다. 지난 리뷰에서 보관한 두 패치 원문을 따로 꺼내 단일 제출 명령으로 채점한 결과도 각각 이번 재현 결과와 일치했다. ## R27 잔여 · 배송 행 저장 호출 검사가 주문 금액 오류를 가린다

정상 패치의 배송 차감 조건에 `ctx.channel.pricesIncludeTax`를 추가한 제출을 만들었다. 신고된 세금 포함 주문은 고치지만 세금 별도 주문에서는 배송비 차감을 건너뛰는 부분 수정이다. 단일 제출 채점 결과는 **통과 4, 실패 0, 판정 불가 2**였다. 직접 취소와 환불 동반 취소 각각의 세금 별도 전체 취소에서 배송 행 저장 호출이 없다는 검사가 예외를 냈다. 서버 메서드는 이미 정상 반환했고 주문 저장 금액과 반환 금액도 읽을 수 있었지만, 공식 결과에는 두 금액이 모두 빠졌다. [해당 검사](https://github.com/hyeonhb/ontosary/blob/3858a32/experiments/domain-model/s2/trial/angular-shipping/observe.mjs#L106-L115)

별도 진단에서는 같은 제출 사본과 여섯 입력을 사용하고, 배송 행 저장 여부를 기록한 후 금액까지 읽었다. 문제의 두 사례에서 주문 저장 시점과 종료 시점의 네 금액은 모두 `1000 / 1200 / 1000 / 1200`이었다. 기대값은 모두 0이다. 나머지 네 사례는 기대값과 일치했다. 이 오류는 메모리 저장소에 실제 전달된 값에서 드러나며 DB 재조회에 대한 가정이 필요하지 않다. [패치 원문·공식 판정·별도 진단값](evidence/2026-11-26-shipping-grading-inclusive-only.json)

## 개발 세션에 전달할 보완 지시

PR #107에서 배송 행 저장 호출의 차이가 이미 확인한 주문 금액 오류를 가리는 경우를 보완해 주세요. 구현 방법은 개발 세션이 정합니다.

- 위 재현 자료의 `patch` 문자열을 같은 단일 제출 경로로 실행해 주세요. 세금 별도 전체 취소 두 건은 기대값·실제 저장 금액과 함께 **업무 실패**, 나머지 네 건은 **통과**여야 합니다.
- 저장 호출 방식이 다르다는 사실만으로 성공이나 업무 실패를 단정하지 않도록 해 주세요. 확인한 업무 불일치는 보존하고, 관측 밖의 의존성이나 실제 결과를 확인할 수 없는 사례에는 기존 판정 불가 기준을 적용해 주세요.
- 이 반례가 4통과·2실패로 바뀌고 기존 12개 제출의 판정과 두 보완 반례의 근거가 유지되면 완료입니다. PR에 결과와 재현 명령을 남겨 주세요. 범위는 기존 메모리 관측과 여섯 사례이며 참가 모델 호출은 0회입니다.
