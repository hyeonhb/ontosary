# 개발 세션 지시문 — Excalidraw 화살표 지우기 패치 A/B/C 비교

이전에 작성한 지우개 기록을 주면 다른 변경에서 실제 패치가 더 자주 성공하는지, 같은 품질까지 드는 조사 비용이 줄어드는지 확인해 주세요. 주 비교는 **C 대 A**입니다. B 대 A는 같은 지식을 일반 문서로 제공한 효과를, C 대 B는 표현 방식의 차이를 해석하는 데 씁니다. 기존 실행·계측 도구를 재사용해 아래 **6개 독립 세션의 첫 패치**를 수집·채점하고 결과 PR로 인계하세요. 이 문서는 진행자용입니다.

## 참가자가 받는 것

세 조건 모두 Excalidraw 수정 직전 커밋 `e32836f799b65f978cbf4877eab7ffc42c6e6494`의 소스·당시 일반 문서·설치된 의존성과 [동결한 사용자 요청](../../experiments/first-use/excalidraw-followup/request.md)을 받습니다. 패치를 제출하는 방법도 동일하게 안내하세요.

| 조건 | 시작 시 직접 제공할 자료 |
| --- | --- |
| A | 공통 자료만 제공 |
| B | 공통 자료와 서술형 개발 문서. C 원문을 일반 문단으로 풀어 쓰되 네 관계, 성립 조건, 근거 위치, 검토 후보, 불확실성과 출처를 보존 |
| C | 공통 자료와 [동결 기록 원문](../../experiments/first-use/excalidraw-eraser/note.md). Git blob `d2a5f20ed74f44cafa2873f94b558f5415cbb62d`와 같은 내용 |

첫 호출 전에 B의 각 주장을 C 원문과 대조하고 실제 전달본을 고정하세요. 두 자료의 근거 링크와 이용 가능 범위도 같게 두세요. 낡은 설명을 최신화하거나 화살표에 유리한 부분만 발췌하거나 후속 해법을 보태면 비교 의미가 달라집니다. B와 C는 같은 방식으로 처음부터 전달하고 읽을지 여부는 작업자에게 맡깁니다.

## 독립 실행과 첫 제출

두 묶음에 A/B/C를 하나씩 배정해 **조건별 2회** 실행하세요. 묶음 안 순서는 사전에 섞어 기록합니다. 여섯 세션 모두 새 대화·독립된 깨끗한 작업 사본에서 시작하고, 기존 로그인 경로로 `gpt-6.2-sol`·`medium`을 요청합니다. 소스 검색, 편집, 로컬 테스트와 가용 도구는 동일하게 제공하세요. 미래 Git 이력, 인터넷 검색, 정답 PR, 검토자용 자료, 다른 작업자의 대화·패치·테스트 결과에 접근할 수 없게 합니다. 서버 모델명을 확인할 수 없으면 요청값과 확인 상태를 따로 기록하세요.

작업자는 시간 안에 직접 조사·수정·테스트할 수 있습니다. 최초 제출 시점에 신규 파일을 포함한 패치와 실행 기록을 고정하고 해당 세션을 끝내세요. 숨은 채점 결과를 알려 주거나, 진행자가 패치를 고치거나, 결과에 따라 다시 제출시키지 않습니다.

## 패치 채점

참가 호출 전에 같은 채점 경로로 수정 직전본에서 일반 화살표가 남고, 기준 수정본 `a89a03c66ccbd3d44078be78a82d7adfb8f05953`에서 아래 기준이 모두 통과하는지 확인하세요. 이후 조건명을 가린 각 첫 패치를 깨끗한 직전본에 적용하고, 검토자가 보관한 동일한 관측 코드와 기존 올가미 테스트로 판정합니다. [기준 장면과 재현 방법](2026-11-27-excalidraw-followup-independent-review.md)

**완전 성공**은 패치 적용, 다음 세 동작, 기존 올가미 테스트 **6/6**을 모두 충족하는 경우입니다. 중간 포인터 표본 없이 두 화살표를 가로질러 손을 뗀 뒤의 상태를 봅니다.

| 원래 요소 ID | 삭제 플래그 | 비삭제 장면에 포함 |
| --- | --- | --- |
| 경로 안 일반 화살표 `ordinary` | true | 아니요 |
| 경로 안 잠긴 화살표 `locked` | false | 예 |
| 경로 밖 일반 화살표 `off-path` | false | 예 |

[관측 코드](../../experiments/first-use/excalidraw-followup/reviewer/arrow-probe.tsx)는 일반 화살표가 남아도 테스트가 통과할 수 있습니다. 원래 두 요소 장면과 세 번째 요소를 추가한 장면 **양쪽의 `ARROW_SCENE` 출력**을 읽고, 각 장면에 해당하는 ID별 플래그와 포함 여부를 표와 대조하세요. 관측 누락은 통과로 세지 않습니다. 구현 방식과 upstream diff 일치 여부는 채점 항목에 넣지 않습니다.

작업자가 떨어진 두 포인터 표본으로 결함을 직접 재현했는지, 그 회귀 테스트를 패치에 남겼는지는 별도 관찰입니다. 잠긴 화살표의 보존은 이미 명시한 요구입니다. 기록의 기여를 설명할 때는 제출 패치와 실제 조사 기록에서 확인되는 판단을 인용하세요.

## 예산·중단·비용 집계

| 단위 | 작업자 경과 시간 | 누적 입력 | 누적 출력 |
| --- | ---: | ---: | ---: |
| 한 세션 | 12분 | 400,000토큰 | 8,000토큰 |
| 여섯 세션 합계 | 72분 | 2,400,000토큰 | 48,000토큰 |

- 경과 시간은 과업 전달부터 첫 제출 또는 중단까지이며 작업자의 도구·테스트 대기도 포함합니다. 공통 환경 준비와 독립 채점은 별도로 집계하세요. B/C 자료를 읽는 입력은 해당 세션 비용에 포함합니다.
- 시간 만료 시 작업을 중단합니다. 입력·출력 중 하나라도 세션 한도에 도달하면 해당 세션의 다음 모델 호출을 막고, 전체 한도에 도달하면 남은 집행을 중단하세요. 응답 후 사용량이 확인되는 경로에서는 확인된 시점에 멈추고 마지막 응답의 초과분까지 기록합니다. 초과분을 잘라 쓰거나 남은 예산을 다른 세션의 한도로 이전하지 않습니다.
- 실패·미제출·시간 만료·예산 도달은 원래 배정에 남깁니다. 환경·제공자 오류와 패치 자체의 실패는 구분하세요. 공통 채점 대조 실패, 자료 노출, 모델 불일치, 계측 결측 등으로 공정성이나 남은 예산을 확인할 수 없으면 영향을 받는 실행을 보류하고 증거를 인계하세요. 대체 실행·추가 참가 호출·새 유료 경로는 이번 예산에 포함하지 않습니다.
- 세션별 첫 제출까지의 시간, 도구 호출 수, 입력·출력 토큰을 실패한 시도까지 합산하세요. 캐시 입력은 입력의 부분집합, 추론 출력은 출력의 부분집합으로 표시하고, 기록 작성·검토·B 변환의 일회성 비용은 별도 표기합니다. 과거 비용을 모르면 결측으로 남기세요.

## 결과 인계

예정된 여섯 자리를 모두 표에 남기고 조건별 완전 성공 수를 **각각 /2**로 보고하세요. 각 패치의 세 동작·올가미 결과, 실패 원인이나 미실행 사유, 비용과 첫 패치를 연결해 모델 재호출 없이 판정을 검토할 수 있게 합니다. 모두 성공하면 두 묶음에서 같은 품질까지의 비용 방향이 반복되는지 보세요. 결과가 엇갈리거나 기록이 비용만 늘려도 그 관측으로 마감합니다. 이 한 과업이 검증하는 것은 동결 기록의 전달 효과이며, FCA의 기록 작성 기여와 사람의 사용 의향은 별도 질문입니다.
