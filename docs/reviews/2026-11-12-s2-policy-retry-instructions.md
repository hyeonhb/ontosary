# S2 감사·시간 제한 보완 및 단일 정책 시험 재개 지시 — 2026-11-12

## 목표와 범위

미분류 snapshot의 자동 closing 편입과 준비 명령의 중첩 시간 제한을 보완한 뒤, [직전 지시](2026-11-12-s2-single-policy-test-instructions.md)의 동일 정책 한 행 시험을 재개한다. **새45분 회차 하나** 안에서 수정·검증·준비·시험·정리·인계를 마친다. 이전 남은 시간을 재개하거나 두 보완과 실행에 별도45분씩 배정하지 않는다.

승인된 변경은 clone arg0가 정확히 `2013397009`(`0x78020011`)일 때의 ALLOW 한 행뿐이다. 추가 권한 확대·AppArmor/sysctl/capability/NNP 변경·후보/CLI 교체·실제 자격 증명 전달·로그인/갱신·provider/모델 호출·본 비교는 결과 리뷰 뒤 별도로 결정한다. 이번 지시 작성은 실제 실행이 아니며 개발 세션에서 아래 순서대로 진행한다.

## 기준과 독립 리뷰

최초 작업 명령에서 UTC와 host monotonic을 기록한다. AGENTS, PROGRESS, ARCHITECTURE, ROADMAP, CONTRIBUTING을 읽고 원격/브랜치/사용자 변경을 확인한다. 기준은 main `5d723b4`(PR #50)이며 실제 시작 head와 차이를 기록한다. [직전 결과](2026-11-12-s2-single-policy-test.md)와 [정책 후보](2026-11-11-s2-namespace-policy-proposal.md)를 읽는다.

- 독립 리뷰는 실제 VM 부팅/container/후보 적용0회와 부팅 전 정리 기록을 확인했다. 정책 효과는 미관찰이다. 증거58파일/13archive/내부657파일, 고정 분석6+closing6 감사 재현, 기존1682파일 불변, 최종 도구14파일 일치, pnpm check304·Python13테스트가 확인됐다. 새 VM 실행은 하지 않았다.
- package.py는 분석 목록 밖 snapshot을 모두 closing으로 편입한다. 임시 복제본에 미승인 실행 명령을 기록한 snapshot을 넣어도 포장/최종 검증이 통과했다. 현재 실제 closing6개는 검사·포장·종료 명령이지만, 미분류 거부 계약은 미완료다.
- 준비는 회차 약708.649초에450초 명령 timeout으로 종료됐다. 환경 마감1200초까지491.351초가 남았다. wrapper의450초, host-prepare의subprocess450초·Lima7분 등이 독립적으로 설정돼 있었다. 환경20분을 모두 사용한 실패가 아니다.

과거 보고·원시 증거·scope/index는 보존한다. 새 판정과 정정은 이번 결과에 남긴다. 제품 코어·모델/B/C·평가기·배포 ID·공유 lifecycle는 유지한다. R11 unresolved·R12 기존 범위·production/live 거부·trialAuthorized/readyForTrial=false·results=null을 유지한다.

## 1. 미분류 snapshot을 포장 전에 거부한다

`single-policy-test/`의 package/scope/snapshot 경로를 필요한 만큼만 수정한다. 새 회차 경로는 명시적으로 전달하고 과거 출력 디렉터리로 쓰지 못하게 한다. `analysis` 밖 파일 전체를 `closing`으로 만드는 glob 분류를 제거한다.

작업 계획에 허용한 종료 작업의 **정확한 command/args·단계**를 고정하고, 해당 명령을 실행할 때 생성한 snapshot ID와 hash를 closing 등록부에 기록한다. 고정 분석 목록과 명시적 closing 등록부의 합집합이 실제 snapshot 집합과 정확히 같아야 한다. ID 중복·분석/closing 중복·누락·미등록·허용되지 않은 명령/단계·hash 차이를 거부한다. 단순히 `python3`나 파일명 접두어만 맞으면 허용하지 않는다.

포장 시 발견한 미등록 항목을 사후 closing으로 편입하지 않는다. 분석 동작이면 분석 범위와 감사 결과를 명시적으로 다시 고정해야 하며, 분석 동결 뒤 새 runtime 실행은 이번 계획상 허용하지 않는다. 감사/종료/포장의 자기 참조 hash 순환은 피하되 전체 최종 index에서 closing 파일·archive 내부까지 검증한다. index 자체는 자기 hash 대상이 아니다.

실제 이전 자료를 사용해 다음을 검증한다.

- 기존11+close1 및 현재6+closing6을 새 설명 메타데이터로 검증하되 원본을 변경하지 않는다.
- 등록된 closing 추가 뒤 고정 분석 감사 결과는 동일하다.
- 미등록 snapshot 추가와 허용 밖 runtime 명령을 closing으로 등록하려는 시도가 **실제 package 진입점**에서 실패한다. scope.classify 단독 테스트만으로 대신하지 않는다.
- 허용 명령과 같은 executable이지만 다른 args/단계인 항목, 중복 ID, 대상 누락/변조를 거부한다.
- 최종 index가 closing 변조와 누락도 거부한다. 거부 경로가 부분적인 성공 결과를 남기지 않도록 출력 준비/공개 순서를 확인한다.

## 2. 환경 준비의 모든 제한을 같은 마감에서 계산한다

환경 마감은 **회차 최초 시계부터20분**이다. host monotonic과 UTC의 절대 마감을 한 곳에서 만들고, wrapper→host-prepare→다운로드/압축 해제→Lima start가 그 계약을 전달받도록 한다. 같은 호스트의 남은 시간은 실행 직전에 다시 계산하고 양쪽 시계 기준 잔여 중 작은 값을 사용한다. snapshot 생성/선행 단계에 소비한 시간도 포함한다.

이전450초·7분·240초 값을 근거 없이 그대로 물려주거나 모두1200초로 치환하지 않는다. 각 단계가 새 전체 예산을 갖지 않도록 한다. 더 짧은 별도 제한이 필요하다면 목적과 값·환경 잔여와의 관계를 계획에 명시한다. Lima의 고정 버전 `--timeout`이 어느 구간을 제한하는지 확인하고, 전체 외부 마감이 다운로드/부팅/준비까지 포함하도록 한다. VM 내부 monotonic과 호스트 monotonic을 같은 시계로 취급하지 않는다.

로컬 fake clock/짧은 가짜 subprocess로 검증한다. 실제로 수백 초 기다리는 테스트는 만들지 않는다.

- 환경 잔여가450초보다 충분히 클 때 과거450초가 숨은 외부 종료 원인으로 남지 않는다.
- 선행 다운로드나 snapshot 생성 시간이 뒤 단계의 잔여에서 차감된다.
- 중첩 단계가 전체 예산을 다시 시작하지 않고, 잔여0/음수면 새 명령을 시작하지 않는다.
- UTC/monotonic 중 더 이른 마감, timeout/실패 시 종료 요청·ledger·정리 전환을 확인한다.
- 실제 실행 ledger에 요청 제한/유효 제한/환경 마감/남은 시간/종료 이유를 남긴다. 준비 wrapper의 process group 종료는 실제 agent 전체 종료 보장이 아니다.

두 보완의 국소 테스트가 통과하기 전 VM을 시작하지 않는다. 기존 helper 복사본을 또 늘리는 대신 해당 시험에 필요한 작은 함수/인자를 재사용한다. 범용 스케줄러·새 runner·대규모 리팩터링은 제외한다.

## 3. 동일한 한 행 시험을 재개한다

직전 지시의 정책·대조·종료 계약을 유지한다. 미실행 초안 helper를 그대로 검증된 실행기로 간주하지 않는다. 필요한 실제 실행 코드와 아래 시작 전 검사를 시간 내 마련하지 못하면 실행하지 않고 보완 결과만 인계한다.

1. 같은 Lima/VZ·runtime·CLI0.167.0-alpha.3.2·Node22.19.0과 기존 제한을 사용한다. 원래/후보는 동일 고정 이미지·trace 옵션·합성 입력/명령, 서로 새로운 상태/source/output을 사용한다. 기존 검증 cache는 사용 전 hash를 확인하고 보존한다. 새 cache/소유 자원의 정리는 직전 계약을 따르며 이번에 영구 cache/VM 운영 구조를 도입하지 않는다.
2. 원래 정책1회에서 첫 namespace clone flags `0x78020011`의 EPERM과 parent의 합성 source/material 양성 동작을 확인한다. 기준이 예상과 다르면 후보를 시작하지 않는다.
3. 실제 기본 OCI seccomp 전체를 복제하고 아래 한 행만 추가한다. container 전용 profile에만 적용하며 start 전에 실제 native Spec을 대조한다. CLI 지원 형식/직렬화 때문에 의미가 달라지면 중단한다. 동적 ID/소유 경로의 대응은 사전에 열거하고 seccomp/default/architecture·AppArmor·UID/capability/NNP·mount 접근·자원 정책 차이를 숨기지 않는다.

```json
{"names":["clone"],"action":"SCMP_ACT_ALLOW","args":[{"index":0,"op":"SCMP_CMP_EQ","value":2013397009}]}
```

4. 후보는 실제 시작1회만 허용한다. clone 반환값/PID와 부모·자식 관계를 관찰하고 사전 점검/실제 명령 준비의 bwrap 호출을 구분한다. 여전히 clone이 거부되거나 다음 syscall/LSM에서 실패하면 결과를 기록하고 멈춘다. 두 번째 정책 변경·flags 확대·추가 trace 실행을 하지 않는다. payload까지 성공해도 그 사실까지만 기록한다.
5. payload15초/단위 외부120초를 유지한다. 새 namespace 자손이 생길 수 있으므로 부모 CLI exit만으로 완료하지 않는다. 기존 검증된 종료/정리 도구를 재사용해 소유 cgroup·runtime task/PID·pending 요청·container 부재를 확인한 뒤 진단을 수집한다. 그 확인을 마련하지 못하면 후보를 시작하지 않는다. credential/상태 저장소 전체를 수집하지 않는다.

일반 환경 준비용 다운로드와 worker 네트워크를 구분하고 worker network none을 유지한다. 실제 자격 증명·host home·키체인·socket·전체 사용자 config/env는 제공/조사하지 않는다. 기존 AppArmor·NNP1·capability0·RO root/cgroup·UID/GID1000·CPU2·메모리4GiB·PID256·tmp64MiB를 유지한다. 추가 권한, 다른 후보/API/proxy, 실제 인증/provider/model 연결은 금지한다.

## 비용 상한과 중단 기준

이 회차는 최초 시계부터45분, 신규 유료 비용0, 소유 VM 최대1개·container 최대2개(원래1/후보1)다. 기계적인 실행 전 인자/경로 오류 수정은 근거가 있을 때1회까지이고, 실패한 후보를 재시작하지 않는다. 이전 누적 측정값12602.02857974998초와 마지막 직렬화의 보수적 상한5초를 각각 유지하고 이번 측정/누적 상한을 분리한다.

| 경과 | 마감 |
| --- | --- |
| 10분 | 두 보완의 국소 테스트와 실행 계획 확인. 준비가 안 되면 동적 시험 착수를 포기하고 보완 인계 |
| 20분 | 환경·동일 이미지·원래 정책 대조·후보 시작 전 검사를 완료. 남은 환경 시간이 없으면 새 준비 명령을 시작하지 않음 |
| 30분 | 후보 관찰 완료 목표. 다음 차단을 해결하는 추가 탐색은 하지 않음 |

실제 정책 차이 초과, 기준/버전 불일치, 추가 권한 필요, 종료/소유권 확인 불가, 예상 밖 파일/네트워크 접근, 각 마감 도달 시 즉시 새 실행을 막는다. 원인을 해결하기 위해 시간을 초기화하지 않는다. 소유 자원만 정리하고 정책/입력 불변성을 확인하며 잔여 복구 항목이 있으면 공개한다.

이번에도 환경 문제로 정책 관찰에 도달하지 못하거나 추가 계층 차단이 확인되면 같은 후보의 미세 조정을 자동으로 반복하지 않는다. 결과와 추가 투자 가치를 인계하고 실행 경계/환경 운영 방식은 사용자와 별도로 결정한다. 이는 후보 포기나 새 구조 구현 승인이 아니다.

## 검증·산출물과 완료 조건

수정 범위는 실험 내부 snapshot 등록/분류·포장, 환경 deadline 전달, 필요한 단일 정책 실행/정리 코드와 관련 테스트·맥락 문서다. 과거 증거·제품·평가기·모델/B/C·공유 lifecycle는 유지한다. 불가피한 공유 코드 변경이 생기면 영향 회귀와 예산 내 가능성을 먼저 검토한다.

새 보고서는 `docs/reviews/2026-11-12-s2-policy-retry.md`, 증거는 `experiments/domain-model/s2/verification/2026-11-12-policy-retry/`에 저장한다. 실제 날짜가 바뀌면 맞춘다. 기존 `2026-11-12-single-policy-test`를 출력 대상으로 재사용하지 않는다.

`pnpm check`, 보완 부정 사례·정책 한 행 검사, 실제 포장/저장 증거 재검증, 문서 링크/변경 범위 검사를 실행한다. 새 audit은 명시적 snapshot 범위와 실제 입력·동적 실행 여부를 재현해야 한다. TS/제품/평가기 변경이 없으면 S2 build·Vendure7·pnpm experiment 전체 반복은 불필요하다. 과거13테스트 통과만으로 새 결함 해결을 대신하지 않는다.

완료 상태를 **보완 구현·시험 관찰·정리**로 구분한다. 기술 관찰은 `first-clone-passed-next-blocked` / `clone-still-denied` / `synthetic-payload-completed` / `inconclusive` 중 근거에 맞게 기록한다. 실제 적용0회이면 정책 효과를 판정하지 않는다. 테스트 실패·정리 미완료·계약 위반은 별도 blocked 사유다. 두 보완의 재현/회귀, 승인된 시험 또는 근거 있는 중단,45분 내 비용·정리·인계가 완료 조건이며 성공 실행은 강제하지 않는다.

보고서에 독립 리뷰 두 항목의 수정/검증 결과, 계획/실행 시간 제한, 원래/후보 OCI diff·원시 trace·실제 분모, snapshot 분석/closing 등록 목록, 최종 전체 index, 입력 불변·자원 정리·비용과 후속 선택을 포함한다. PROGRESS·ARCHITECTURE·ROADMAP·REVIEW_CONTEXT와 필요한 DECISIONS를 실제 결과로 갱신하고 CONTRIBUTING의 저장소 반영 절차를 따른다. 추가 권한 확대·자격 증명 전달·모델 호출과 본 비교는 결과 리뷰 뒤 결정한다.
