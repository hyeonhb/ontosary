# 개발 지시문 — Excalidraw 지우개 기록을 재사용할 후속 변경 한 건 선정

실제 Excalidraw 변경 이력에서, 이전에 기록한 관계를 알면 **무엇을 수정하거나 어떤 동작을 보존해야 할지** 판단할 수 있는 후속 변경 한 건을 찾아 주세요. 이번 산출물은 과업 선정 근거입니다. agent가 기록을 읽었을 때의 효과는 이후 비교에서 측정합니다.

## 동결할 자료와 탐색 범위

사용할 기록은 [`cc5a8d6`의 note.md](https://github.com/hyeonhb/ontosary/blob/cc5a8d67e80b51efde14bddf0b7801e8d1cfd051/experiments/first-use/excalidraw-eraser/note.md) 그대로입니다. Git blob은 `d2a5f20ed74f44cafa2873f94b558f5415cbb62d`입니다. 관계는 ① 포인터 궤적을 로컬 점열로 저장하는 과정, ② 제자리에서 뗀 끝점의 보정과 작은 획의 보존, ③ 지우개 이동 중 삭제 후보 수집, ④ 입력을 뗄 때 장면 삭제 확정입니다. 후속 코드에서 바뀐 설명이나 새로 알게 된 예외는 선정 보고서에만 적어 주세요.

[지우개 교정 사례 #9946](https://github.com/excalidraw/excalidraw/pull/9946)이 반영된 뒤, upstream 기본 브랜치에 실제로 들어간 별도 변경을 대상으로 합니다. 후속 변경 직전 트리가 교정 커밋 `1161f1b8ba860a34602fc4aa211ea9f5b28c30eb`을 포함하는지 확인하세요. 같은 패치의 이식·되돌리기·재적용이나 기존 작은 점 장면을 그대로 반복하는 사례는 제외합니다. 반대로 지우개 파일을 직접 수정하지 않아도, 동결한 관계가 다른 사용자 동작의 판단에 쓰인다면 후보가 될 수 있습니다.

조사 시작 때 upstream 끝 SHA, 살펴볼 이력 범위와 후보 순서를 먼저 기록하세요. 예를 들어 관계에 연결된 경로나 용어로 이력을 좁힌 뒤 병합이 이른 순서로 검토하고, 아래 기준을 모두 충족하는 첫 건에서 멈출 수 있습니다. 조사한 후보와 제외 이유는 한 줄씩이면 됩니다.

## 한 건을 채택할 기준

- **독립된 사용자 요구가 있다.** 당시 이슈·변경 요청 등에서 사용자의 동작, 기대 결과, 기존 동작 중 보존할 부분을 설명할 수 있어야 합니다. 참가자에게 줄 짧은 과업 문구를 써 주세요. 문구에 사후 리뷰의 힌트, 수정 파일·함수, 정답 diff는 넣지 않습니다.
- **동결한 관계가 구체적인 판단 한 가지에 쓰인다.** 원문 한 대목을 고르고 후속 변경 직전 소스에서 여전히 성립하는 조건을 확인하세요. “이 관계를 알면 어떤 잘못된 수정이나 빠진 회귀를 알아챌 수 있는가?”에 실제 입력과 예상 결과로 답해 주세요. 심볼 이름이나 파일 경로만 겹치면 근거가 부족합니다. 특히 #9946에서 자유 그리기 충돌 판정이 바뀌었으므로 오래된 세부 동작을 그대로 전제하지 마세요.
- **제3자가 결과를 판정할 수 있다.** 검토자용 자료에 공개 이슈·PR 또는 커밋, 변경 직전·직후 전체 SHA, 해당 판단을 뒷받침하는 코드·테스트를 연결하세요. 동일 입력에서 달라져야 할 관측값과 양쪽에서 유지돼야 할 대조 동작을 하나씩 제시하세요. 기존 테스트를 실행했다면 명령과 결과를, 소스만 확인했다면 아직 실행해야 할 항목을 표시하세요. 이 단계에서 새 평가기를 만들 필요는 없습니다.

## 완료와 인계

결과 PR 첫 문단에서 **선정한 한 건, 재사용 가능한 관계, 그 관계로 구별할 두 동작**을 읽을 수 있게 해 주세요. 참가자용 문구와 사후 해법이 들어 있는 검토 근거는 따로 전달할 수 있게 두세요. 이력상 연결이 있어도 기록이 오래돼 오히려 잘못된 판단을 유도할 수 있다면 그 근거도 남겨 주세요. 선정은 효용의 가설이며 실제 upstream 작성자가 Ontosary를 사용했다는 뜻은 아닙니다.

정해 둔 범위 안에 적격 사례가 없으면 가장 가까운 후보와 탈락 이유를 인계하면 완료입니다. 다음 단계는 선정 결과 리뷰에서 결정합니다. 이번 작업은 공개 이력과 기존 자료 조사로 마치며, 참가 모델 호출·A/B/C 실행·컴파일러 호환이나 FCA 상한 변경은 범위 밖입니다.

컴파일러 호환성과 대규모 프로젝트의 FCA 적용 범위는 [별도 제품 과제](../ROADMAP.md#실제-프로젝트의-분석-호환성과-fca-범위)로 추적합니다. 이번 선정에는 동결 기록과 upstream 근거를 사용하고, FCA가 기록 작성에 기여했다는 평가는 실제 후보를 생성해 검토할 수 있을 때 진행합니다.
