# 독립 리뷰 맥락

마지막 리뷰: 2026-11-04, Asia/Seoul. [상세 보고](2026-11-04-poc-review.md) · [다음 작업 지시](NEXT_PLAN.md).

## 역할과 사용자 문제

이 세션은 구현과 분리된 Technical & Product Reviewer다. 도메인 이해·관련 규칙 탐색·근거 검토·지식 유지 비용이 줄어드는지 평가한다. 온톨로지/FCA/LLM은 수단이다. 기본 원칙은 [PRODUCT](../PRODUCT.md), 가설 목록은 [RESEARCH](../RESEARCH.md)를 참조한다.

기존 소스·테스트·설정·ROADMAP·PROGRESS를 직접 수정하지 않는다. 검증 명령을 실행하고 `docs/reviews/`에 보고서와 독립 재현 자료를 보존한다. 별도 개발 세션에 전달할 독립적 지시문을 작성하되 명시적 요청 없이 메시지를 전송하지 않는다.

## 검토본과 실제 검증

첫 리뷰는 커밋 없는 main/untracked 초기 작업본이다. [42개 기존 파일 fingerprint](evidence/2026-11-04-source-fingerprints.json)으로 식별한다. 이후 같은 파일명·라인이 같은 내용이라는 가정을 하지 않는다.

- `pnpm check`: 3개 파일/41개 테스트, 타입 검사, 예제 production build 통과.
- 복제본 실험: 비교 4/4, 타입 6/함수 13, predicate 6 supported/7 unsupported, FCA 13×26/형식 개념 20/후보 8/관계 8.
- 독립 FCA: 4객체×3속성 4,096행렬이 객체 부분집합 oracle과 일치.
- 독립 논리: 16식/144입력 평가, 256쌍 비교/336개 반례 실행 확인. 4,096조합 허용·8,192조합 사전 거부.
- 코드 사실·후보·승인 지식의 구분, 심볼 충돌 구분, 전제와 한계 출력은 확인했다.

첫 리뷰이므로 반복 발생 추세는 아직 없다. 공통 실패 양상은 지원하는 구문의 하위에 미지원 실행 의미가 숨겨졌을 때 정규화가 이를 건너뛰는 것이다. 기존 테스트 통과가 이 경계의 정확성을 보장하지 않았다.

## 판단과 가설 상태

권장 방향은 현 방향 유지, 정확성 수정 우선이다. 현재 Gate 1 미통과; Gate 2/3 미검증; Gate 4 부분 확인이나 미통과; Gate 5 미통과다. [NEXT_PLAN](NEXT_PLAN.md)의 R1/R2 차단 작업이 바로 다음 하나다. R3는 corpus 측정 전 별도 작은 후속 작업이다.

FCA 수학적 열거와 올바른 IR의 유한 비교에는 근거가 있다. 반면 현재 정규화가 supported로 내보내는 모든 함수를 올바르게 표현한다는 주장은 반례로 깨졌다. FCA의 업무 의미 유용성, 일반 도구/LLM 대비 효과, 실무 도입·유지 비용은 미검증이다. FCA 의미 가설이 실패했다고 결론 낼 자료도 없다.

경쟁 확인은 Semgrep/CodeQL 공식 기능 문서의 제한된 확인뿐이다. 이 도구들과 동일 과업 성능 비교나 최신 범용 에이전트 평가를 하지 않았다. 설치 이유의 가설은 적은 설정으로 관련 규칙 후보·소스·전제·실행 가능한 차이 입력을 연결해 검토 비용을 줄이는 것이다.

## 다음 리뷰에서 볼 것

1. R1/R2가 TypeScript 진단 0인 fixture에서 차단되는가? false proof를 Unsupported로 줄이는 해결도 허용한다.
2. 정상 지원 사례와 CLI/API 계약은 유지되는가? 이때만 수정된 범위에서 Gate 1을 재평가한다.
3. 실제 corpus 2개, 독립 수동 라벨 20~30개에 revision·라이선스·분모·미지원 사유가 있는가?
4. 검색/LSP와 동일 facts의 단순 속성 그룹보다 FCA가 검토 과업을 개선하는가? 논리 반례의 효과를 별도로 관찰했는가?
5. 정답 도달률·근거 정확성·잘못된 확신·검토 시간·준비 및 유지 비용을 함께 측정했는가? 실패·미지원 과업을 분모에서 누락하지 않는가?

FCA 순증분이 없으면 기본 사용을 축소하고, 규칙 비교가 더 가치 있으면 제품 범위를 그 과업에 맞춘다. 실제 과업 증거 없이 LLM·SMT·프레임워크 플러그인·승인 UI로 확장하지 않는다. 날짜별 리뷰와 원시 증거는 보존하고 새 판단은 새 기록으로 남긴다.
