# Ontosary 이해하기

Ontosary는 기존 프로젝트의 코드와 도메인 지식을 연결해, AI agent와 개발자가 프로젝트를 이해하고 수정하는 데 도움을 주려는 도구다. 이 안내서는 프로젝트에 처음 참여하거나 설계의 이유를 다시 확인하려는 사람을 위한 문서다.

## 읽는 순서

| 궁금한 것 | 읽을 문서 |
|---|---|
| 어떤 문제에서 출발했으며 온톨로지와 FCA는 왜 사용하는가? | [핵심 아이디어](idea.md) |
| 코드 분석, 도메인 모델, 조회는 어떻게 연결되는가? | [아키텍처 안내](architecture.md) |
| 설치하고 실제 명령을 실행하려면? | [저장소 README](../../README.md) |
| 정확한 지원 문법과 데이터 계약은 무엇인가? | [구현 명세](../ARCHITECTURE.md) |
| 왜 이런 선택을 했고 무엇을 검증해야 하는가? | [결정 기록](../DECISIONS.md) · [연구 가설](../RESEARCH.md) |

먼저 핵심 아이디어에서 용어와 역할을 이해한 뒤 아키텍처를 읽는 순서를 권한다. 코드 파일이나 개별 개발 지시를 읽지 않아도 전체 설명을 따라갈 수 있도록 구성했다.

## 그림의 범위를 읽는 법

이 안내서의 도식은 세 종류다. 각 그림의 제목과 설명에 범위를 표시한다. 화살표는 자료 흐름이나 표시된 참조를 뜻하며, 그 자체로 업무상 인과관계나 기능의 구현 완료를 뜻하지 않는다.

| 표시 | 뜻 |
|---|---|
| **개념 설명** | 목표와 역할을 설명한다. 모든 상자가 구현된 것은 아니다. |
| **구현된 구조** | 확인한 코드에서 실제 동작하는 경계를 나타낸다. |
| **합의된 설계** | 다음 구현이 따라갈 구조다. 완료 여부는 별도로 확인한다. |

확인 기준은 **2026-11-09 S2 준비 독립 리뷰**다. 정적 분석 코어와 S1 도메인 모델 파일럿의 보완은 검증됐고, S2의 준비·조회·배포 구조도 확인했다. 다만 [독립 리뷰](../reviews/2026-11-09-s2-preparation-independent-review.md)에서 제출 코드 평가의 세 문제를 발견해 보완이 필요하며, 본 비교는 미실행이고 readyForTrial=false다. agent의 수정 성능 개선과 FCA의 추가 가치는 아직 입증하지 않았다.

최신 작업 상태는 [PROGRESS](../PROGRESS.md), 단계별 계획은 [ROADMAP](../ROADMAP.md)에서 확인한다. 날짜별 리뷰의 수치나 한 번의 성공을 제품 전체의 보장으로 읽지 않는다.

## 문서의 역할

이 안내서는 **문제·용어·구조·판단의 이유**를 설명하는 지속 관리 문서다. 다음 작업의 체크리스트나 세션 인계는 `docs/reviews/`의 날짜별 문서에 둔다. 과거 검증 기록은 보존하고, 이 안내서는 새로 확인한 사실에 맞게 갱신한다.

- 제품 목표·원칙의 기준: [PRODUCT](../PRODUCT.md)
- 구현 지원 범위·공개 계약의 기준: [ARCHITECTURE](../ARCHITECTURE.md)
- 현재 상태와 다음 작업의 기준: [PROGRESS](../PROGRESS.md) · [ROADMAP](../ROADMAP.md)
- 그림의 원본·갱신 방법: [도식 관리](../diagrams/README.md)

목표나 용어가 바뀌면 핵심 아이디어를, 모듈 경계나 자료 흐름이 바뀌면 아키텍처 안내와 해당 도식을 함께 갱신한다. 특히 ‘합의된 설계’를 ‘구현된 구조’로 바꿀 때는 연결된 검증 근거와 확인 기준도 갱신한다.
