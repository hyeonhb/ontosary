## 현재 우선순위 — 2026-11-08 목표 정렬

최종 목표는 기존 프로젝트를 agent가 도메인을 이해하고 수정하기 좋은 프로젝트로 전환하도록 돕는 것이다. 업무 개념·관련 코드 탐색은 첫 사용 경로다. 아래 S1~S3이 현재의 실행 순서이며, 기존 번호별 PoC/연구 단계는 경과와 후속 후보로 보존한다(ADR-020).

1. **S1 · 보완 독립 검증 완료:** R6/R7 해결, 174테스트·4비교·V2 15파일 재현을 확인했다. [독립 리뷰](reviews/2026-11-08-domain-model-contract-independent-review.md). 모델 의미·FCA 결과는 유지되며 agent 효용은 미검증이다.
2. **S2 · 자료·평가·계측 준비 구현, 전체 실행 환경은 차단:** [실행 전 준비 인계](reviews/2026-11-10-s2-trial-preparation.md)에 공통 계약·C/대응표·공개 검사·macOS probe·새 배포를 기록했다. 사용자 결정으로 token hard cap은 필수 조건에서 제외했다(ADR-029). 다음은 detached 자손의 종료 경계 보완, 실제 CLI 격리 조건 확인, 독립 리뷰와 C 사람 대응 검토다. 본 비교는 별도 승인 뒤 진행하며 readyForTrial=false·H-O/H-F 미검증을 유지한다.
3. **S3 · 효과가 관찰된 경우:** 변경 후 모델 근거 만료·재검토·갱신을 실험한다. 그 비용을 포함해 재사용 가치가 있는지 판단한 뒤 제품 계약·구조 변경을 선택한다.

[R9 modal 데이터 전달 보완 지시](reviews/2026-11-09-s2-modal-fix-instructions.md)와 [직전 R8/R9/R10 지시](reviews/2026-11-09-s2-contract-fix-instructions.md)는 지원 범위 내 독립 검증을 마쳤다. 새 실행 전 준비 범위는 ADR-028로 승인됐다. 현재 지시는 준비 결과의 리뷰 인계까지이며 본 비교 실행 승인은 포함하지 않는다.

기존 관찰은 환경 준비와 제한된 분석의 재현 근거다. 모델 품질이나 agent 성능 개선의 증거는 아직 없다. 무효/부정 결과에 따라 표현·속성·범위를 재설계하며, 주요 기술 투자/온톨로지 형식/코드 구조 전환은 사용자와 결정한다.

## 0.1 · 논리 정규화 정확성 수정 — 구현·회귀 검증 완료, 재검토 가능

2026-11-04 독립 리뷰의 R1(enum receiver 평가 생략)·R2(explicit this에 따른 인자 위치 오류)를 먼저 차단한다. 41개 기존 테스트 통과만으로 Gate 1을 통과했다고 보지 않는다. NEXT_PLAN의 회귀·실행 대조·CLI 상태 검증을 완료한 뒤 지원 경계에 한해 재평가한다. 과거 리뷰 증거는 보존한다.

2026-11-06 R1은 직접 enum 선언 receiver만 허용하고 R2는 explicit this를 거부하는 방식으로 수정했다. 76개 자동 테스트와 기존 독립 probe 재실행을 통과했다. 상세 근거는 [개발 인계](reviews/2026-11-06-normalization-fix.md)에 있다. 이는 모든 문법의 건전성 증명이나 독립 리뷰 승인이 아니다.

R3(mixed TS/JS의 files 집계)도 별도 작업으로 수정했다. files는 실제 분석한 구현 파일만 포함하며 제외 구현 파일의 근거를 omissions에 남긴다. 6개 회귀 테스트를 추가해 전체 82개와 실험·독립 probe가 통과했다. [NEXT_PLAN 이행 점검](reviews/2026-11-06-next-plan-completion.md)을 참조한다. 이번 정확성 수정에서 FCA·LLM·SMT·UI·지원 문법 확장을 진행하지 않는다.

## 1 · 실제 코드 coverage와 정답셋 — 관찰 자료 완료, 사람 검토 대기

1. 공개/사용 허가된 작은 TS 프로젝트 두 개를 선정하고 고정 revision·라이선스·분석 범위를 기록한다. 사적 데이터를 자동 수집하지 않는다.
2. 코드 사실과 업무 의미를 분리한 수동 라벨 20~30개를 만들고 누락·오연결·미지원 사유를 집계한다.
3. 일반 타입만 공유하는 넓은 그룹, 기술적 UI 타입 그룹의 검토 유용성을 평가한다.
4. 불편이 반복되는 문법 하나만 선택해 실패 fixture → 구현 → 회귀 테스트 순서로 지원을 넓힌다.

완료 조건: 재현 가능한 corpus, 분모가 명확한 coverage, 실패 사례, 검토 결과. 이 근거로 FCA 필터·변수 매핑·분석 범위 선택의 우선순위를 정한다.

2026-11-07: [관찰 자료](reviews/2026-11-07-corpus-observation.md)를 구축했다. 공개 corpus 2개·agent 작성 코드 사실 24개·원시 실패/상한/미지원 결과·단순 그룹/FCA 검토표와 재현 runner가 있다. 라벨 22개 일치/2개 미지원, 사전 비교 0/2 지원이다. 사람의 라벨 승인·업무 의미 평가·검토 시간은 남아 있으므로 단계 1 전체 완료로 표시하지 않는다. 다음 한 작업은 사용자 과업 검토이며 문법 확장은 그 근거를 얻은 뒤 선택한다.

## 2 · A/B/C/D 비교 실험

2026-11-08 이후 이 설계는 **모델 구축 방법 H-F의 후속 후보**다. 현재 S1보다 먼저 LLM/SMT 제품 기능을 추가하는 지시가 아니다. agent의 모델 사용 효과 H-O는 위 S2에서 별도로 평가한다.

LLM 단독 / TS+LLM / +FCA / +논리 검증의 효과를 비교한다. 정답셋, 모델·프롬프트·비용 한도, 평가 절차를 고정한다. 의미 precision/recall, 근거 정확성, 오해 비율, 검토 시간, 유지 비용을 보고한다.

완료 조건: 긍정·부정 결과를 포함하는 보고서와 원시 데이터. FCA나 검증이 효과가 없으면 강제하지 않고 축소·변경한다. 실제 필요가 확인되면 SMT를 작은 하위 실험으로 도입한다.
