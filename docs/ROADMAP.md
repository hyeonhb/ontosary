4. 불편이 반복되는 문법 하나만 선택해 실패 fixture → 구현 → 회귀 테스트 순서로 지원을 넓힌다.

완료 조건: 재현 가능한 corpus, 분모가 명확한 coverage, 실패 사례, 검토 결과. 이 근거로 FCA 필터·변수 매핑·분석 범위 선택의 우선순위를 정한다.

2026-11-07: [관찰 자료](reviews/2026-11-07-corpus-observation.md)를 구축했다. 공개 corpus 2개·agent 작성 코드 사실 24개·원시 실패/상한/미지원 결과·단순 그룹/FCA 검토표와 재현 runner가 있다. 라벨 22개 일치/2개 미지원, 사전 비교 0/2 지원이다. 사람의 라벨 승인·업무 의미 평가·검토 시간은 남아 있으므로 단계 1 전체 완료로 표시하지 않는다. 다음 한 작업은 사용자 과업 검토이며 문법 확장은 그 근거를 얻은 뒤 선택한다.

## 2 · A/B/C/D 비교 실험

2026-11-08 이후 이 설계는 **모델 구축 방법 H-F의 후속 후보**다. 현재 S1보다 먼저 LLM/SMT 제품 기능을 추가하는 지시가 아니다. agent의 모델 사용 효과 H-O는 위 S2에서 별도로 평가한다.

LLM 단독 / TS+LLM / +FCA / +논리 검증의 효과를 비교한다. 정답셋, 모델·프롬프트·비용 한도, 평가 절차를 고정한다. 의미 precision/recall, 근거 정확성, 오해 비율, 검토 시간, 유지 비용을 보고한다.

완료 조건: 긍정·부정 결과를 포함하는 보고서와 원시 데이터. FCA나 검증이 효과가 없으면 강제하지 않고 축소·변경한다. 실제 필요가 확인되면 SMT를 작은 하위 실험으로 도입한다.

## 3 · 제품 후보 / Public Beta

문서 추출·LLM 의미 해석·Semantic Alignment, 후보 승인/병합/보류, 승인 지식 버전 관리, 코드 변경 불일치 탐지, React UI 연결, Next.js Server/Client 분석, AI 코딩 에이전트 연동, 필요시 온톨로지 표준을 검토한다.

완료 조건: 반복 사용에서 근거 있는 개선, 최소 사용성과 설치 재현성, 비용·실패 모드의 설명. 학술적으로 완전한 검증만을 공개의 전제조건으로 삼지는 않는다.
