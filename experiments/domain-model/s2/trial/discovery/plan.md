# 실행 전 고정할 비교 단위

Vendure 534e6003534f74761e82de1b8c6061cba89945d1, 동일 업무 요청, Sol medium. 세 블록의 순서는 ABC / BCA / CAB. 매 슬롯은 새 대화·새 원본 사본으로 시작하고 다른 세션의 답이나 평가 결과를 전달하지 않는다. 첫 응답부터 끝까지 한 세션이다. 각 응답은 한 가지 작업을 요청한다. 프롬프트에는 해당 세션의 업무·사용법·그동안의 대화와 해당 작업 응답만 전달한다. 서버 모델명이 없으면 미확인으로 표시하고 불일치·조건 누출·계측 장애 시 후속 실행을 중지한다.

- 주 지표는 첫 수정 전 1회 제출한 영향 범위가 네 가지 판정 항목을 모두 충족한 수 / 예정 3이다. 항목별 점수와 실제 근거도 남긴다. 부 지표는 타입 검사와 모든 문구·절차 사례를 통과한 수 / 예정 3이다. 탐색과 구현은 별도로 보고한다. 동률이면 성공 여부별 및 실패 포함 총비용을 함께 비교한다. 작은 표본의 관측 차이를 일반적인 개선으로 해석하지 않는다.
- 세션당 첫 모델 요청부터 제출까지 30분, 최대 모델 요청 24회(오류 포함), 검색·읽기 등 모든 작업 응답 합계 최대 24회, 한 응답 4,096 UTF-8 bytes. 모델 응답이 잘못되거나 요청이 실패해도 같은 슬롯의 예산을 소모한다. 종료/시간 초과 시 마지막으로 확정된 탐색 제출만 유효하고 finish 없는 최종 소스는 미제출이다. 실패를 다른 세션으로 교체하지 않는다.
- 세션당 누적 입력 160,000, 누적 출력 8,000 토큰의 운영 상한을 제안한다. 로그인 경로의 누적 hard cap은 검증되지 않았다. 각 응답 이후 usage를 합산하고 도달 시 다음 요청을 막는다. 마지막 응답의 초과분은 전액 기록하며 원시 usage가 누락되면 집행을 중지하고 해당 합계를 미확정으로 표시한다. 취소·타임아웃도 사용량과 시간을 보존한다. 총 운영 상한은 입력 1,440,000, 출력 72,000 토큰, 참가 시간 270분, 요청 216회다. 토큰 수치는 절대 결제 한도가 아니다.
- 계획 추정은 세션당 12–20회, 회당 고정/기본 입력 1,200 토큰, 앞선 왕복당 350–650 토큰(도구 결과와 참가자 응답), 회당 출력 150–300 토큰을 가정한다. 전체 이력을 다시 보낼 때 입력은 n×1,200 + n(n−1)/2×(350–650)이다. 세션당 입력 37,500–147,500, 출력 1,800–6,000. 조건별 3회 입력 112,500–442,500, 출력 5,400–18,000. 9회 입력 337,500–1,327,500, 출력 16,200–54,000. 응답/도구 처리 30–60초를 가정하면 9회 순차 참가 시간 54–180분이다. 조건별로 같은 범위를 사용한다. 제공사 실측·청구액·사람의 자료 작성/유지 시간은 미측정이다.
- 호출별 요청 ID·모델 요청/응답 표식·성공/실패·원시 usage·경과 시간을 보존한다. 입력에 포함된 cached와 출력에 포함된 reasoning은 부분량으로 별도 표기한다. 같은 호출의 누적 이벤트를 중복 합산하지 않는다. 사용량 없는 실패는 0으로 채우지 않는다. 도구는 종류·조건·성공/오류·실제 반환 bytes·행/건수와 벽시계 시간을 별도 집계한다. 예정/시작/제출/통과/실패/미지원/결측·중단 사유를 분리한다. 환경 준비·외부 채점 시간은 참가 시간 밖이다.
