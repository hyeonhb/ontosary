# S2 설계 초안 — 미실행, 평가자 전용

S1 독립 리뷰 이후 범위를 확정한다. 이번 문서는 agent에 제공하는 모델 자료에 포함하지 않는다. Vendure 원문/서버를 수정하거나 비교 세션을 실행하지 않았다. 이미 내용을 아는 사례이므로 개발용 pilot이며 일반화 평가가 아니다.

## 과업 후보와 계약

가상 요구: “관리자 주문 취소 요청의 `reason`은 전송 전에 trim한 비어 있지 않은 문자열이어야 한다. 직접 취소와 환불 중 일부 취소에 같은 계약을 적용하고, 대화상자 닫기는 요청을 발생시키지 않아야 한다. 취소 없이 수행하는 환불은 유지한다.”

현재 generated `CancelOrderInput.reason`은 optional nullable string이다. 따라서 클라이언트에서 더 강한 로컬 입력 계약/검증을 두는 변경과 GraphQL schema를 필수로 변경하는 변경을 구분해야 한다. 이 pilot은 **클라이언트 로컬 제약**만 적용할 후보이며 generated 파일이나 서버 schema는 바꾸지 않는다. 실제 제품 요구가 모든 클라이언트의 강제 정책이라면 서버 검증·schema/codegen 계약 변경이 별도로 필요하고, 이 pilot만으로 달성했다고 채점하지 않는다.

S2 시작 전에 평가자가 원래 revision의 직접 취소/환불 준비 및 service 전달 동작을 작은 고정 fixture로 추출하고 기존 동작 oracle를 검토·동결해야 한다. Angular/DB 전체 런타임 성공 대신 fixture의 검증 범위를 명시한다. 단순히 답을 적은 테스트나 agent가 만든 테스트만으로 통과를 판정하지 않는다. 추출 fixture가 원문과 같은 분기/입력 의미를 유지하는지 별도 검토하며, 미확정 상태에서는 실행하지 않는다.

평가자 기대 검토 경로:

- 취소 dialog `select()`와 환불 dialog `select()`의 `cancel` 입력 생성에 reason 정규화/빈 값 처리가 필요하다. 함수 이름만 찾은 변경은 후자를 놓칠 수 있다.
- `OrderDetailComponent.cancelOrder()`의 입력 유무와 `refundOrder()`의 `input.cancel.lines?.length` 분기를 유지한다. 취소 없는 환불에서 취소 요청을 새로 만들면 실패다.
- `OrderDataService.cancelOrder()` 경계의 검증/타입과 각 호출부 일관성을 검토한다. 기존 nullable GraphQL 타입을 로컬에서 좁히는 방법은 하나로 강제하지 않는다.
- 두 dialog의 `cancel()`은 입력 없는 닫기다. 이름이 비슷하다고 주문 취소 요청으로 바꾸면 실패다.
- 주문 메뉴/버튼의 기존 HTML 조건, `cancelShipping`, 부분 취소 lines의 의미를 유지한다. generated 파일에 직접 필수 필드를 추가하거나 모든 환불에 취소를 강제하면 전제 위반이다.
- 모델 밖 추가 취소 호출은 독립 검색으로 점검한다. 이 목록은 전체 앱 영향 범위의 정답을 보증하지 않는다.

고정 fixture 기대 사례(아직 구현 안 함): 정상 reason/앞뒤 공백/빈 문자열/공백만/null/undefined; active 주문 lines 생략; 부분 취소의 양수 항목; 두 dialog dismiss; 환불+취소와 환불만; 취소 실패 결과 이후 환불 방지의 기존 분기. 제출 값, service 호출 인자/횟수, 회귀 여부를 확인한다. HTML은 수동 검토 항목이며 자동 TS coverage로 세지 않는다.

## 조건과 오염 통제

같은 agent의 정확한 모델 ID/버전·reasoning 설정·도구·소스 revision·lock·기존 문서·환경·토큰/시간 예산을 실행 전에 고정한다. 모델 ID/예산은 현재 `null`(미정)이다. A/B/C 각각 독립 세션에서 최소 3회 반복하는 pilot을 제안한다. 순서는 기록된 seed로 무작위 배정하며 이전 답변·diff·평가 기대 자료를 다음 세션에 전달하지 않는다. 동일 작업을 본 리뷰어의 기억과 모델 제공자의 선택 편향은 한계로 공개한다.

- A: 코드 + 기존 upstream 문서 + 동일 과업 문장.
- B: A + 동결 S1 모델/근거/사용 안내.
- C: A + B와 **동등한 명제·근거·미확인 질문**을 담은 일반 Markdown 문서. 정보 누락과 token 양 차이를 기록하고 별도 사람이 동등성을 검토한다. 그래프 형식의 효과를 추가 정보량 효과와 구분한다.

B의 파일 목록/hash를 실행 전에 동결한다. 이 파일 및 숨긴 oracle/정답 diff/실패 조건은 제공하지 않는다. 별도 workspace 복제와 컨텍스트 격리, 공통 설치 준비, 조건별 변경 가능한 경로와 불가 경로를 고정한다. S1 작성자가 직접 비교 agent의 대화에 힌트를 보태지 않는다. 조건별 결과를 블라인드 ID로 평가하고 사람이 수정한 추가 작업도 기록한다.

## 측정과 비용

각 실행에서 변경 누락(경로별), 잘못된 수정/회귀, 전제 위반, 고정 oracle 성공, 추가 검증의 적절성, 실제 변경 diff, 실패·중단 사유를 기록한다. 토큰과 agent wall time, 환경 준비 비용, 모델/일반 문서 작성·사람 검토·재작업 시간을 모두 별도 측정한다. 사람 비용을 agent 실행 시간으로 대체하지 않는다. 모델 없이도 직접 검색으로 찾은 경로는 인정한다.

현재 모든 S2 성능·token/time·사람 재작업 수치는 **null/미측정**이다. 아직 agent 비교·실제 Vendure 변경·평가 fixture 구현을 하지 않았다. 모델의 agent 효용 H-O와 이번 FCA의 구축 기여 H-F는 별개다. pilot에서 H-O 개선이 관찰되고 비용이 감당 가능할 때만 S3의 source 변경/근거 만료·모델 갱신 비용 실험으로 진행한다.
