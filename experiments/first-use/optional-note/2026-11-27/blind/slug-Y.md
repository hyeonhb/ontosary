1. `vendure/packages/core/src/service/services/product.service.ts`의 `ProductService.findOneBySlug`에서 `getRawOne()`으로 상품 ID를 선택하기 전에 `product.channels`를 `ctx.channelId`로 내부 조인한다. `findOne`은 선택된 ID의 채널 소속만 검사하므로, 다른 채널의 상품이 먼저 선택되면 현재 채널에 일치하는 상품이 있어도 조회가 비게 된다.
2. 모든 번역의 slug를 검색하고, 요청 언어 → 채널 기본 언어 → 기타 언어 순으로 후보를 정렬하는 기존 동작을 유지한다. 삭제된 상품을 후보에서 제외하고, `findOne(ctx, id, relations)`을 통해 관계 로딩과 응답 번역을 유지한다. `vendure/packages/core/src/api/resolvers/shop/shop-products.resolver.ts`의 `ShopProductsResolver.product`가 적용하는 ID 조회 우선순위, 비활성 상품 제외, 비공개 패싯 값 필터링도 유지한다.
3. `vendure/packages/core/e2e/product-channel.e2e-spec.ts`에서 `SECOND_CHANNEL_TOKEN`과 `THIRD_CHANNEL_TOKEN`으로 각각 같은 언어와 slug를 가진 서로 다른 상품을 생성한다. 두 채널의 Shop API가 각각 자기 상품 ID를 반환하고, 상대 채널에만 있는 slug는 `null`을 반환하는지 확인한다. `vendure/packages/core/e2e/product.e2e-spec.ts`에서는 ID·slug 조회, 여러 에셋이 있는 상품, 기본 언어 폴백, 다른 언어의 slug로 조회했을 때 요청 언어로 응답하는 동작, 없는 slug의 `null` 응답, 삭제된 상품의 slug 재사용을 검증한다.
