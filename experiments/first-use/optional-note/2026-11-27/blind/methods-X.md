1. `vendure/packages/core/src/api/config/get-final-vendure-schema.ts`의 `buildSchemaFromVendureConfig`에서 Shop API 스키마를 구성할 때, `vendure/packages/core/src/api/config/graphql-custom-fields.ts`의 `addGraphQLCustomFields`가 생성한 `PaymentMethodCustomFields`와 `ShippingMethodCustomFields`를 각각 `PublicPaymentMethod.customFields`와 `PublicShippingMethod.customFields`에 연결합니다. 공개 필드가 하나 이상 있을 때만 연결해, 미설정 또는 비공개 필드만 있는 경우에는 `customFields`를 생략합니다. 기존 Shop API 규칙에 따라 `public` 생략은 공개로 처리하고 `public: false`와 `internal: true`는 제외합니다.

2. `vendure/packages/core/src/api/config/generate-resolvers.ts`의 `generateCustomFieldResolvers`에서 새 필드가 생성된 공개 타입에 기존 `customFields` 리졸버를 등록합니다. 관계 필드 조회에 필요한 원본 엔티티 ID와 기존 구조체 처리를 재사용합니다. 두 활성 목록은 `getActivePaymentMethods`와 `getActiveShippingMethods`를 계속 호출해 현재 채널, 결제 활성 여부, 배송 소프트 삭제, 요청 언어 처리를 유지합니다. `vendure/packages/core/src/api/schema/shop-api/shop.api.graphql`에 정의된 기존 반환 타입, 필드, null 허용 여부를 보존합니다. 운영 설정의 공개 범위와 Admin API 및 주문별 `eligible*Methods`의 계약도 유지합니다.

3. `vendure/packages/core/e2e/payment-method.e2e-spec.ts`와 `vendure/packages/core/e2e/shipping-method.e2e-spec.ts`에서 Admin API로 저장한 공개 값이 기존 Shop 조회에 함께 반환되는지 검증합니다. 두 수단 모두 공개·비공개·내부 필드가 섞인 경우, 비공개·내부 필드만 있는 경우, 필드 미설정인 경우를 확인합니다. 번역 필드의 요청 언어 및 대체 언어, 공개 관계 필드의 해석, 다른 채널 수단·비활성 결제 수단·삭제된 배송 수단의 제외, 기존 필드만 요청하는 조회도 검증합니다. `vendure/packages/core/src/api/config/graphql-custom-fields.spec.ts`의 공개 필터 테스트를 기준으로 기존 Admin 및 견적 스키마도 비교합니다.
